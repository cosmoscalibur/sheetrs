## [0.4.1] — 2026-11-13

### Changed

- The `Book` of the Python and WebAssembly packages reads nothing when it is made and keeps nothing of the workbook, and the properties that were derived from its statistics are gone: `sheet_names`, `sheets`, `defined_names`, `date_system`, `has_macros` and the eleven `total_*` in Python, and `sheetNames`, `sheets`, `definedNames`, `dateSystem`, `hasMacros` and the `total*` in WebAssembly. What a `Book` says about the workbook is `stats()`, a method that reads it each time it is called and gives a `Stats` (the totals, `sheets`, `has_macros` and `defined_names`; in WebAssembly `toJSON()`, `hasMacros` and `definedNames`). The date system is in `inspect()`, and a workbook of an unsupported one raises in `stats()` and in every query, not when the `Book` is made. `Book.stats` is a method now, not a property.
- The demo of `docs/` reads the statistics with `stats()`.
- Lower the time and the peak memory of `sheetc build`: the dependency graph is built straight into its compressed form and freed once the evaluation order is known (no second copy of the adjacency, no copy of each node's edges while it is walked), the graph node of a cell is found through the row of the sorted node list instead of a hash table of every position, and the references that lie inside an output are no longer collected only to be skipped. On the generated workbooks of `docs/performance.md`, `formulas.xlsx` builds in 6.8 s instead of 8.3 s with 1355 MB instead of 1598 MB, and `data.xlsx` in 7.6 s instead of 9.1 s with 1540 MB instead of 1942 MB; the executables are byte-identical.
- Keep the two operands of a binary operator in one allocation (`Expr::Binary(op, Box<[Expr; 2]>)`): the build of `formulas.xlsx` peaks at 1309 MB (from 1355 MB), and its executable starts with 423 MB instead of 455 MB and answers a request in 1.9 s instead of 2.2 s. The executables are byte-identical; the JSON of `sheetc build --emit-ir` writes the operands of a binary operator as an array.
- Free the text of the formulas of the model as soon as `sheetc build` and `sheetc calculate` have lowered them: `compile` accepts the model by value (`compile(model, &spec)`, besides `compile(&model, &spec)`, which leaves the model as it is). On the generated workbooks of `docs/performance.md`, `formulas.xlsx` peaks at 1152 MB instead of 1309 MB; time and the program are unchanged.
- Replace `bincode`, which is unmaintained (its 3.0.0 release is a tombstone that does not compile), with `postcard` as the encoding of the program and of the blocks of constants inside an executable built by `sheetc build`: the executable of a workbook without declared inputs and outputs is about half the size (`data.xlsx` 207 → 115 MB, `formulas.xlsx` 194 → 94 MB) and starts with less memory.
- Update `zip` to 9 (a part name that is not valid text is skipped when reading and is an error when writing), `sha2` to 0.11, `pprof` to 0.15 and `serde_json` to 1.0.154.
- A plan of `sheetrs edit` that deletes rows, columns, sheets or names, or replaces text, ends with the engine calculating every formula again. The analysis that decided which formulas a deletion leaves stale (and wrote `#REF!` or calculated only those) is removed: on the 2.4-million-formula workbook it cost 15-16 s of an ODS run (7-8 s of an XLSX one) and, where nearly every formula is stale, spared nothing. What a cell holds is the value its formula gives now; the result a file cached is not a fidelity goal (see `docs/approved-differences.md`). `--dry-run` no longer reads the workbook to say which formulas are given `#REF!`.
- Lint a workbook of millions of formulas with every default rule in about half the time and 40 % less peak memory (`formulas.xlsx`, 2.4 M formulas: 32.9 → 16.6 s and 1088 → 660 MB; the ODS of the same workbook 37.2 → 21.6 s and 1123 → 695 MB). The findings, their order and the output of every format do not change. CALC202 reads each formula once (the references and the links with other sheets came from two parses), keeps the dependency graph of the workbook in a flat arena (`CellDependencies`) instead of a map of vectors, and finds the loops over positions in a vector; VUL601 groups the formulas of a sheet by the hash of their text (16 bytes each) instead of a map of the texts; CALC201 reads its parameters once per sheet and VUL606 scans a formula once for all of its patterns; REF310 skips the formulas with no colon.
- `sheetrs stats` on an ODS no longer converts every formula to Excel's notation, which the counts do not use:
  2.4 M formulas take 2.9 s instead of 5.4 s, with the same output. The XLSX read is unchanged.
- The XLSX and ODS writers allocate less per cell: the content of a cell is read into buffers kept between cells, the
  attributes of an ODS cell are read in one pass, and a cell that does not change is copied as it is. Rewriting a
  workbook is 15-25 % faster (14 MB peak, unchanged) and the output is byte for byte the same.
- The tests of `sheetc` that mixed several behaviors or had vague names are split and have short names that say the behavior (`locale_flag_is_refused_at_run_time`, `info_lists_inputs_and_outputs`, `explicit_config_replaces_the_discovered_one`, ...). Two checks that only fixed a design decision (that there is no `--dialect` flag, and that `outputs` is no longer a key of `sheetc.toml`) are removed: an unknown flag and an unknown key are already refused by their own tests.
- `CONTRIBUTING.md` (*Test Patterns*): a test is named for the behavior it checks, tests behavior and not design, and checks one behavior.

### Fixed

- Remove the mentions of the flags `--recalculate` and `--recalculate-on-open`, which do not exist, from the documentation and the comments of `sheetrs-rt-wasm`.
- Fix `sheetrs edit --delete-columns` on an ODS taking five times as long as on the XLSX of the same workbook (136-160 s against 22 s, 2.4 M formulas): the empty run that closes each row up to the last column of the sheet was written shorter by the columns deleted, so the next read of the file (the recalculation of the plan) took it for formatted cells and built about 16 000 of them per row. The run keeps reaching the last column.
- Fix `sheetrs query --find --include-formulas` (and `Book.find` with `include_formulas`) not finishing on a workbook with millions of formulas: the inference of the format of each result read the file again for every different range a formula refers to, and looked for the cells of each range through all the cells read. It reads each sheet whole after eight windows and finds the cells of a range by position; the 2.4-million-formula workbook is searched in 18 s (XLSX) and 23 s (ODS), where it had not finished in five minutes. The answers do not change.
- Keep `zip` below 9.1. From 9.1 it depends on `getrandom` with `wasm_js` on wasm32 whatever its features: the WebAssembly modules of `sheetc` (`sheetrs-rt-template.wasm`) asked the host for five imports of the `wasm-bindgen` glue where they have none, so `sheetc build --target wasm --embed-template` produced modules that no plain host could instantiate, and `wasm-bindgen` was built without its `std` feature, which fails in a release build on Rust 1.99 (the job `wasm npm package` of the CI was red since the update).

## [0.4.0] — 2026-11-12

The API is **experimental and unstable in every layer** (command line, Rust, Python and WebAssembly): it changes without notice and there is no compatibility promise yet. This release is a restructure of the suite, and most of what follows is breaking with respect to 0.3.2. The reference of behavior is LibreOffice 26.8: XLSX and ODS are read and edited with the same capabilities, each file gives what LibreOffice gives for that file, and the differences that were approved are in `docs/approved-differences.md`. The rules that keep the four layers aligned, and the table of what each operation is called in each of them, are in `docs/api-alignment.md`.

### Changed

- **Breaking, executables:** one executable, `sheetrs`, with the subcommands `query`, `edit`, `lint` and `stats`, replaces `sheetquery`, `sheetedit`, `sheetlint` (and its previous name `sheetcli`) and `sheetstats`; `sheetc` has `build`, `calculate`, `inspect`, `verify` and `evaluate`. The release archives carry `sheetrs`, `sheetc` and `sheetrs-rt`. Each tool crate holds its subcommand behind the `cli` feature; without it the libraries do not depend on `clap`, and neither do the WebAssembly and Python packages.
- **Breaking, flags:** the names are the words of the LibreOffice Calc interface and the same for every tool: the input workbook is `-i/--input FILE` (the positional `FILE` is gone), the output is `-o/--output`, `--in-place` replaces the input through a temporary file and a rename (a failure leaves the original as it was; `sheetrs edit` and `sheetc calculate`), `--delete-sheets`, `--delete-names`, `--delete-rows`, `--delete-columns`, `--formula-to-value`, `--list-sheets` and `--list-names` (of `sheetrs query`). Every edit operation takes the array of its targets, and repeated `--replace`/`--with` pairs make a sweep (paired by position). The default configuration file of `sheetrs lint` is `sheetrs.toml`, and the SARIF tool is `sheetrs lint`.
- **Breaking, calculation:** `sheetc calculate` is one form, `calculate -i FILE|PROGRAM.json [--request JSON|@FILE|-] [--range RANGE]… [-o OUT | --in-place] [--json]`; compiled executables take `--request` and `--range` the same way. The request is `{"inputs", "ranges", "majorDimension"}` and the answer is always `{"valueRanges": [{"range", "name", "values"}]}`, as the batch read of a spreadsheet API answers: with declared outputs and no `ranges`, one entry per output with its `name`, and the values of one cell are `[[value]]`. `calculate(inputs, ranges, major)` is the same in every layer. Recalculating a workbook is `calculate -i FILE -o OUT`; `sheetc verify --reference cache|libreoffice` says what the formulas are compared with. `outputs` is only the declaration of what a compiled program exposes (the `settings` sheet, `--settings-file`, `sheetc.toml`). The standard input is read only when asked for (`--request -`, `--serve`).
- **Breaking, formats:** the format of a workbook (XLSX, XLSM, ODS) is read from its content in every layer and is no longer an argument (the extension is never consulted); a file that is none of them is an unsupported-format error that names what it is.
- **Breaking, dates:** by default a number is the serial the file stores; the `dates` flag (`sheetrs query --dates`, `dates=True` in Python, `dates: true` in WebAssembly and in the JSON query) gives a number whose format is a date or a time as `{"type", "value"}` in ISO 8601. The date system is one of the three of LibreOffice Calc (`DateSystem`: 1899-12-30, 1900-01-01, 1904-01-01); an ODS with another null date is an error that says so, and `--date-system` accepts `1899`, `1900` and `1904`.
- **Breaking, Rust:** `sheetrs_io::Book` is the one interface of the library. It holds where a workbook comes from (`Book::from_file`, `from_bytes`, `from_reader`), its `format()`, what it reads (`workbook`, `analysis_into`, `selection_into`, `date_system`, `defined_names`, `sheet_names`, `external_urls`) and, with the feature `write`, the operations pending on it. Each tool adds its verbs in its own crate as a trait to import: `BookQuery` (`query`, `range`, `find`), `BookEdit` (`delete_sheets`, `delete_names`, `formula_to_value`, `delete_rows`, `delete_columns`, `replace`, `calculate`, `explain`, `value_ranges`, `write`, `write_in_place`, `write_to`), `BookCompile` (`compile`, `calculate`, `inspect`, `verify`, `build_wasm`, `template`), `BookLint::lint` and `BookStats::stats`. The results are typed values (`LintReport`, `Stats`, `ValueRanges`, `Report`, `Diagnostic`, `Inspection`) with explicit conversions (`to_json`, `to_sarif`, `to_text`).
- **Breaking, crates:** the crates are named `sheetrs-<role>`: `sheetrs-core` is `sheetrs-io` (the workbook model, the readers and, behind the feature `write`, the XLSX and ODS writers), the rules and the linter are in `sheetrs-linter`, and there are `sheetrs-protocol` (the typed JSON of the tools), `sheetrs-query`, `sheetrs-stats`, `sheetrs-edit`, `sheetrs-formula`, `sheetrs-engine`, `sheetrs-compiler`, `sheetrs-answer` (writes the answer of a program into the workbook it was made from), `sheetrs-cli`, `sheetrs-wasm`, `sheetrs-rt-wasm` and `sheetrs-py`. `sheetrs-edit` depends on the compiler (the engine is not injected). The libraries report typed errors (`thiserror`; `anyhow` only in the executables); public names lose their `get_` prefix and parse through `FromStr`/`From`; the public types are `Send + Sync`; `#[non_exhaustive]` marks the enums that can grow; modules nobody uses outside their crate are private; every publishable crate has a README, a description, keywords and categories, and all are at version 0.4.0 (`rust-version` 1.99).
- **Breaking, edit plan:** the operations of a `Book` are not a sequence, in every layer: each one is written against the workbook as it is, in its original rows and columns, and the planner decides the order and the passes (cells written and replacements, then the calculation, then one pass with the conversion of formulas to values and the deletions). The order they are pushed in and how they are split into calls change nothing; step by step is one `write` or `save` per step. `--dry-run` (which needs no output) and `explain` show the passes.
- **Recalculation of an edit:** what a deletion or a replacement leaves stale is calculated again by the engine, and the workbook is saved with fresh results and no mark to recalculate it when it is opened; only if the engine cannot calculate it is the workbook marked, and the report says so with the diagnostic `RECALC_NOT_SUPPORTED`. The formulas that are stale are found from the formulas, not from the type of the operation: when none is there is no recalculation pass, a formula that reads a deleted cell is written as `#REF!` without the engine, and the engine calculates the rest. A conversion of formulas to values reads what the workbook has, so a conversion and a deletion in one command are one pass.
- **Python:** the package is one object, `sheetrs.Book`, with `range` (several ranges in one pass), `find`, `lint`, `stats`, `inspect`, `calculate`, the operations that accumulate (`delete_sheets`, `delete_names`, `formula_to_value`, `delete_rows`, `delete_columns`, `replace`) and `save`, the cut that plans and runs them. A query with operations pending raises `PendingOperationsError`; an error cell is a `CellError`. It reads the workbook once when it is made and keeps what it found as properties (`format`, `date_system`, `has_macros`, `sheet_names`, `sheets[name]`, `defined_names`, `stats` and the `total_*`). It takes a path, bytes or a binary stream (`io.BytesIO`) and `save(dest)` writes to a path or a stream; `to_bytes()` gives the bytes. Results are typed (`Stats`, `ValueRanges`, `Report`, `Diagnostic`, `Inspection`, `LintReport`) with `to_dict()`/`to_json()` and, for the lint report, `to_text()` and `to_sarif()`. `sheetrs.evaluate(formula)` and `sheetrs.lint_rules()` are functions of the package. Python 3.13 to 3.15 (SPEC 0), one abi3 wheel per platform.
- **WebAssembly:** the package has one object, `Book`, with the same surface (`lint`, `query`, `range`, `find`, `inspect`, `compile`, the operations of the plan, `save`, `valueRanges`, `explain`, `report`, `dates`, `onDiagnostic`) and typed results with `toJSON()` and `toSarif()`; the free functions are `lintRules`, `evaluateFormula` and `initPanicHook`. The Cargo features `query`, `edit` and `calculate` choose what the module contains.
- **Diagnostics:** structured in every layer: a level (`error`, `warning`, `info`, `debug`), a stable code, the message and its context. The command lines write them on the standard error (`--log-format json` for a record per line, `-q` for the errors only, `-v` and `-vv` for more); Python sends them to the `sheetrs` logger of `logging` and the warnings also to `warnings`; WebAssembly returns them and hands each to `onDiagnostic`.
- **Formulas as LibreOffice shows them:** the readers give a formula in the syntax of its file (Excel's in an XLSX, OpenFormula in an ODS); the linter, the statistics and the compiler work on an analysis form in Excel's notation. `sheetrs query` and `sheetrs edit` see a formula as LibreOffice shows it for that file, and a replacement writes the result back in the syntax of the file.
- **Linter rules:** CPX504–CPX509 report with cell scope; CPX509 counts characters without the namespace prefix of the functions; CALC202 reads the references from the formula AST and has two levels (an error when a cell of the loop holds an error, a warning when only the graph closes it); CALC205 reports only `SUM`, `COUNT`, `COUNTA` and `AVERAGE`; REF307, CPX504, CPX505 and VUL602 read the formula without its literals; REF310 compares value types cell by cell, reports a range only when the cells after it continue the block, and shows the whole block and the suggested range; DATA701, DATA702, DATA703 and DATA704 are corrected (DATA702 does not report formulas), FILE1002 is "Old Spreadsheet", VBA1101 finds ODS macros, REF306 resolves defined names, HID901 tells a very hidden sheet from a hidden one; the violations sort by scope and then rule ID, and the output order is the same on every run. A disabled provider still runs when a rule that depends on it is enabled. The rule reference and the `sheetrs.toml` example are tested against the registry (#50), every rule module documents what it reports and what it does not, and the unused rule stubs are gone. `WalkerRule` hooks take `&mut self` and write the violations into a `&mut Vec<Violation>` sink; the single `WalkerRule` architecture replaces `LinterRule`.
- **Statistics:** `sheetrs stats` groups its output by sheet (per-sheet used cells, errors, empty cells and uncompressed XML size), reports the end of each sheet and its comments, charts and tables, counts only cells with a value or a formula, and counts while it reads, so it does not keep the workbook.
- **Query:** an error cell is `{"error": "#DIV/0!"}`; a formula cell in `General` takes the number format of its result as LibreOffice does; `Find.formatted` searches the text each cell shows; `Find.filtered` leaves out the rows an autofilter hides unless it asks for them; typing into a cell takes the currency symbol and the literal text of the cell format; with `entire_cells` the first match must cover the whole text, and a wildcard `*` takes as little as it can, as LibreOffice does. Notes (`comment`) are read and searched in both formats, and every cell of an array formula reports its formula.
- **Edit, replace:** Find & Replace as LibreOffice does it, over the workbook, a sheet or a range (`--replace`, `--with`, `--scope`, `--regex`, `--wildcards`, `--match-case`, `--entire-cells`, `--in value|formula|comment`, `--formatted`, `--filtered`), in XLSX and ODS: the replacement is entered as if it were typed (a number, a formula or an empty cell) and takes the number format LibreOffice gives it, a formula that refers to another workbook is shown as LibreOffice shows it, and a replacement always reaches the formula cells and makes them constants. A replacement that leaves text that is not a formula is made as LibreOffice makes it (error cell with `Err:5xx`, unknown names in lowercase).
- **Fixtures and tests:** the generators of the binary test fixtures are deterministic and CI checks it; no test judges one format by the other (each file is judged by what LibreOffice gives for it, `sheetrs-io/tests/assets/oracle`); tests are named after the behavior they check, and tests that only verified a design decision were removed.
- **Performance:** the XLSX reader takes 20 % fewer instructions and the ODS reader 36 % fewer (the document is read once); the linter keeps its cells in a compact grid (peak memory of a 6.6-million-cell workbook with every rule from 1.5 GB to 0.6 GB, time halved) and `sheetrs stats` counts while it reads (peak memory of a 39 MB XLSX from 462 MB to 22 MB); REF301 scans each formula once for all the names; `sheetc` lowers formulas on all cores, answers exact `VLOOKUP`/`HLOOKUP` through a hash index, embeds programs in `bincode`, and an executable that exposes every cell starts in milliseconds with a small fixed memory (a 1.2-million-formula workbook builds in 5 s instead of 39 s); a recalculated workbook is deflated at a lower level; a conversion to values of an ODS or an XLSX streams the sheets and keeps at most one row in memory. `docs/performance.md` has the current figures.
- **Dependencies:** `quick-xml` 0.42 and `regex` 1.13 (attribute values follow XML 1.0 normalization; invalid UTF-8 in CDATA is an error), and higher minimum versions of the other dependencies; the minimum Rust version is 1.99; clippy runs with `clippy::all` and `clippy::pedantic` as errors in CI; the rule modules use static `LazyLock<Regex>`; Dependabot groups patch and minor updates and keeps the actions up to date.

### Added

- **`sheetrs query`:** read the cells of an XLSX or an ODS by range, sheet or workbook (`--range`, `--sheet`, `--workbook`, or `--query` with the JSON of `sheetrs-protocol`) with the properties asked for (`value`, `formula`, `number_format`, `display`, `comment`; only those are read), as JSON or one cell per line (`--jsonl`); `display` is the text a person sees, in a locale (`--locale`). `--find` keeps the cells where a text is found as LibreOffice's Find & Replace finds it (literal, regular expression within the subset of ICU that is compared with LibreOffice, or wildcards; match case; entire cells; in the value or in the formula), and `--list-sheets` and `--list-names` give the names of the sheets and the defined names.
- **`sheetrs edit`:** `--formula-to-value` (whole sheets, columns or rows, XLSX and ODS; #11), `--delete-rows` and `--delete-columns` in the coordinates of the input file, and the deletion of sheets and names in both formats. A deletion adjusts the formulas of every sheet, the defined names, merged areas, conditional formats, validations, hyperlinks, filters, notes, manual page breaks, the database and print ranges of an ODS and the shapes and chart series of an XLSX as LibreOffice does: a reference to a deleted cell is `#REF!` and a range shrinks around the deletion; shapes, pictures and charts are placed by the sizes of the rows and columns in the file (in an XLSX the width of a column is in characters, so the position of a shape by columns that differ from the default is an approximation). Peak memory of a conversion alone does not grow with the workbook. Removing every sheet is an error, a result is never written over the input, and a failed write does not remove an output that was there before.
- **`sheetrs lint --format sarif`:** the findings as a SARIF 2.1.0 log (validated against the official schema), besides `human` (the default) and `json`; `sheetrs_linter::output` has the three writers.
- **`sheetc`, the compiler and engine** (formerly the `cosmoscalibur/xlslang` repository): `sheetrs-formula` (a lossless formula AST with a single-pass parser, a canonical printer, reference rewriting and `calc_print`/`calc_read` for LibreOffice's notation), `sheetrs-engine` (a format-independent IR, the function library and a demand-driven evaluator) and `sheetrs-compiler` with `sheetc`: `build` compiles a workbook into a standalone executable (or a WebAssembly module with `--target wasm`), `calculate` compiles and runs in memory, `inspect` reports what a build would find, `verify` recomputes the formulas and compares them with the cache of the file or with LibreOffice, and `evaluate` calculates one formula. Inputs and outputs are declared (the `settings` sheet or `--settings-file`, with metadata) or deduced (the outputs are the formula cells, the inputs the constants a path of dependencies starts from); `--embed-template` makes the workbook its own template, so the executable writes a copy of it with the results (`-o`), answers JSON (`--range`, `--serve`) or both (`--json`); `--meta` and `--info` say what an executable exposes and how it was built; `sheetc.toml` configures the build, with a locale (`en-US`, `en-GB`, `es-ES`, `es-CO`, `es-MX`, a table generated from LibreOffice; `[locale]` can change any field). The compiler warns on manual calculation mode, and `sheetc` stops the build with an error that names what it does not support (`docs/FIDELITY.md#what-stops-a-build`); what depends on an input warns and gives `#NOT_IMPLEMENTED!` when a run meets a case the engine does not reproduce. `INFO("system")`, `INFO("osversion")`, `INFO("release")` and `CELL("filename")` are answered from the machine when the program runs and can be fixed when it is built or run (`--system`, `--osversion`, `--release`, `--directory`, `--filename`, `[host]` in `sheetc.toml`); `--meta` also lists the properties of the document and the defined names it can read, `--version` prints the versions of the compiler and the runtime, and `enable_features` (`LONGTEXT`) joins the `_xlfn._LONGTEXT(…)` text literals that LibreOffice 26.2 wrote.
- **Functions of `sheetc`,** each with oracle rows computed by LibreOffice 26.8 (`FIDELITY.md`): the calendar and series functions, `CELL`, `INFO`, `STYLE`, the complex-number, Bessel and `CONVERT` families, the database functions, depreciation and odd periods, coupons and securities, the statistical distributions and tests, `FORECAST.ETS*`, regressions, frequencies and modes, the dynamic-array functions (`SEQUENCE`, `FILTER`, `SORT`, `UNIQUE`, `TAKE`, `HSTACK`, `TEXTSPLIT`…), the byte-width text functions, `REGEX`, `FOURIER`, the pricing add-in, `LET` and the names of OpenDocument and LibreOffice.
- **Python and WebAssembly:** `sheetrs-py` (PyO3, with type stubs and a pytest suite) and `sheetrs-wasm` (every tool in memory from the bytes of a workbook: no file, process or thread), the web demo in `docs/` (lint, statistics, query, edit, calculate, evaluate and compile to a module that runs in the page) and `scripts/package-wasm.sh`. `sheetc build --target wasm` writes a module of a workbook that needs no imports and no glue; `scripts/build-wasm-rt.sh` builds the two base modules that the release archives carry.
- **Readers:** `Workbook::settings` (the calculation settings a document stores), the named expressions of an ODS, `Workbook::name_conflicts` and the rule REF311 (a defined name defined more than once, with its scopes), `Sheet::state` (`Visible`, `Hidden`, `VeryHidden`), and a selective read (`Selection`, `Window`, `Properties`) that parses only what is asked for: ten rows of a 4-million-cell sheet read in under 10 ms in either format.
- **Documentation and project:** `docs/api-alignment.md`, `docs/performance.md` (the time and memory of every tool on generated workbooks, with the same flows in LibreOffice 26.8.2 and `scripts/bench.py` to measure again), `docs/approved-differences.md`, `docs/references.md`, `docs/environment.md` and `scripts/setup-claude-env.sh` (the environment of Claude Code), the FIDELITY and FUNCTION_NAMES documents of the compiler, installation from GitHub with `uv`, `pip` and `cargo` and the npm tarball of a release.
- **Linter rules:** CALC203 (Double Operator), CALC204 (Approximate Lookup), CALC205 (Double Count), INT401 (Interrupted by Data), INT402 (Interrupted by Empty), INT403 (Interrupted by Other; the three INT rules share one pass), REF309 (Reference to Empty Cell), REF310 (Longer Ref Expected), REF311 (Defined name defined more than once), VUL605 (Legacy Array), VUL606 (Deprecated Function) and DAT706 (Numeric Text Calc); VUL604 detects `LOOKUP`.
- **CI and release:** CI builds, tests and lints the library, builds `sheetrs` and `sheetc` and runs them on a real workbook, checks the WebAssembly package (with a smoke test and the demo in Chromium), checks that the fixtures are deterministic and builds the abi3 wheel for Linux x86_64 and aarch64, tested in Python 3.13, 3.14 and 3.15. A `vX.Y.Z` tag builds the Linux executables, the wheels, the sdist and the npm tarball, smoke-tests them and publishes a release whose notes start with the section of the version in this file; a manual run is a dry run that creates no release. Publishing to crates.io and PyPI is still manual (issue #108). macOS and Windows are issue #99.

### Removed

- The executables `sheetquery`, `sheetedit` (and `sheetcli`), `sheetlint` and `sheetstats`; `sheetc run` (it is `sheetc calculate`), `--recalculate`, the levels of the outputs (`--outputs declared|named|any`), `--dialect` and every Excel-semantics branch of the engine, the support of an arbitrary null date, `sheetrs edit --list-names` (it is `sheetrs query --list-names`), `--include-formulas` of `sheetrs edit`, `--recalculate-on-open`, `--remove-sheets`, `--remove-ranges` and `--delete-cols` (renamed), `verify_workbook` of WebAssembly (the check against a reference is `sheetc verify`) and the `ext` argument of the WebAssembly functions.
- The notation R1C1 (`sheetrs_formula::r1c1`): only A1 is supported, as an approved difference.
- The adjustment of references across sheets (`Sheet1:Sheet3!A1`) by `sheetrs edit` is not implemented: a command that deletes rows, columns or sheets in a workbook with such a formula stops with an error that names issue #75.
- `Calculator`, `Recalculator`, `Source`, `Editor` and the free `read_*` functions of the readers (replaced by `Book`), `WorkbookModifications` and the other types of the writers as public surface, `LinterRule` (replaced by `WalkerRule`), the unused functions `extract_formats_from_xlsx`, `Sheet::cells_in_column`, `Sheet::cells_in_row` and `Sheet::last_data_cell`, `CellReference::to_excel_ref` and `col_to_letter` (`parser_utils::column_letters` is a `Display`), and the stubs REF308, VUL607 and DAT707.

### Fixed

- **Behavior as LibreOffice 26.8 gives it, in the engine and the readers:**
  - Booleans: a number with a boolean format is that number (`IF({0;1},TRUE(),5)`); a function that keeps the boolean format of its argument gives the boolean (`VALUE(TRUE())`, `+TRUE()`); `IF` and `CHOOSE` of arrays take the format of the last branch that ran; the missing `else` of an array is read by what takes it; an ODS `office:boolean-value` that is a number is TRUE unless it is zero.
  - Errors: the error code of every function (`Err:502`, `Err:504`, `Err:508`–`Err:511`, `Err:518`, `Err:523`, `Err:539`…) as LibreOffice gives it and carried through the results (`{"error": "#VALUE!", "code": "Err:502"}`), a literal error where a function wants a reference or an array, the number of arguments each function takes and an argument written empty, a bare `#REF!` per file, a sheet that is not in the workbook, and text with an array that does not parse.
  - Arrays and ranges: a range given to a function of a formula that is not an array formula is met by the cell of the formula, in any sheet; an array is taken one element at a time by a function that takes one value; arrays written in a formula may leave elements out; the array of an operator over a range is the whole range; a reference over several sheets (`Data:Wide!A1:A3`) is the same area on every sheet, in the order of the workbook, and goes through `IF` and `CHOOSE`; the database functions take arrays written in the formula.
  - Text and locale: an empty text is read as LibreOffice reads it from each file (blank in an XLSX, an empty text in an ODS with a paragraph); the text format is never taken from a cell, and an aggregate takes the format of the first argument that holds a number; text is ordered by ICU4X's collator and case is mapped by its case mapper (72,771 pairs compared in seven languages); `CHAR`, `CODE`, `MATCH`, `LOOKUP`, `COUNTIF`, dates up to the year 32767 and regular expressions (the compared subset of ICU) follow LibreOffice.
  - Display: the text a cell shows for a date, a time or an elapsed time is what LibreOffice writes (Julian calendar before 1582-10-15, `#FMT` outside the range of the formatter, `[hh]`/`[mm]`/`[ss]`, the fractions of a second), and `General` is written in scientific notation below `1E-4`; an ODS `office:date-value` before the year 1 is a date.
  - `NORMSINV(0.5)` and every function that reached `erf` at minus zero never returned; `ERF` and `ERFC` follow the algorithm of the C library; `RANDBETWEEN` rounds its limits away from zero; `MATCH`, `VLOOKUP`, `HLOOKUP` and `XLOOKUP` with a text criterion find the number the text shows; the hasher of the engine no longer collides on whole numbers stored as `f64` (a 600,000-row `VLOOKUP` build took 56 s and takes 6 s).
- **ODS:**
  - Dates are numbered from the document's `table:null-date`, and time cells are fractions of a day.
  - A cell with content and no style takes the default style of its row or column; the number formats of every family of data style are read; an error only LibreOffice has keeps its code (`Err:522`); negative times are numbers; a numeric cell in a cell formatted as Text is a number.
  - Formulas: `[#REF!]` and a reference across sheets (`[$T.A2:$V.A4]`) are read as an XLSX writes them, a reference without `$` or with a quoted sheet name is normalized to the XLSX formula, the row separator `|` of an array constant is read, text inside a formula's string literal is not rewritten as a reference, and the comment of a cell is not read as its value; runs of spaces, tabs and line breaks in cell text are kept.
  - Names and settings: a defined name written after the last table no longer takes the table as its scope, and the last-modified date saved by LibreOffice is read.
  - Parsing sheets that end in large repeated row blocks is no longer slow, and hidden rows and columns are stored as ranges.
- **XLSX:**
  - Entity and character references are no longer dropped from element text (#48; `IF(A1<0,"Y","N")` was read as `IF(A10,Y,N)`), and text cells keep their leading and trailing spaces.
  - The cached string result of a formula that reads as a number (`"007"`) is text; an error constant (`t="e"`) is not an empty cell; a range in a cell that holds `#VALUE!` is `#VALUE!`; sheets with an absolute relationship target are found; hidden rows written as `<row hidden="1"/>` are detected.
  - Shared formulas shift whole columns and rows and leave alone what is not a cell (`TOTALSALES2024`, `LOG10(`), and one that would read outside the sheet is `Sheet!#REF!`; the writer no longer writes a second `calcPr`.
- **`sheetrs edit`:**
  - `--delete-sheets` turns the references to the removed sheets into `#REF!`, and `--delete-names` leaves the name unknown in the names that used it; sheets and names whose names contain XML entities (`R&D`) are no longer ignored; the same command gives the same workbook (formula edits were applied in hash order).
  - A conversion to values leaves an empty text where the formula gave an error (as Formula to Value does); a conversion after a deletion converts the results the engine calculates, not the stale ones the file cached; a conversion of an ODS formula that carried a shape or a note stays a formula; an ODS saved by the previous step and the same plan in one pass give the same workbook.
  - A manual page break left before the first row or column is not written, since LibreOffice reads none from a file.
- **`sheetrs lint`:** the output order is the same on every run (#33); REF310 reports the same set of violations on every run and no longer skips the later ranges of a formula (#34); disabling CALC202, CPX504 or ERR102 no longer changes the results of the rules that depend on them (#53); CALC205 no longer overflows a column index on arguments that are not ranges (#69) or reports cross-sheet references as double counts; VUL604 is not triggered by `XLOOKUP`; DATA702 does not report the text a formula returns; the text report no longer prints the `Sheet:` header twice (#70) and lists the cells in row and column order; a configuration naming a rule or category the linter does not know is rejected when parsed in every interface; ERR102 does not count a saved `#NAME?` for a function with the `_xlfn.` prefix; a cell error value that could not be parsed is not reported as an "unknown rule ID"; REF301 documents that it also reports an unused name whose reference is broken.
- **WebAssembly:** `cargo doc` with warnings as errors passes; the writer of a native executable no longer calls `drop` on a file without a destructor on that target; the compiler reads the clock only when `SHEETC_TRACE` is set (reading it panics there).
