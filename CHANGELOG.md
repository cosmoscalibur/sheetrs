## [0.4.2] — 2026-11-17

### Added

- The locale is a property of the workbook (issues #106 and #84): `Book::with_locale` in Rust, `--locale` in `sheetrs edit` (and `sheetrs query`, which had it), `Book(..., locale=...)` in Python, `new Book(bytes, locale)` in WebAssembly. It reaches `calculate`, the recalculation that follows an edit, `TEXT` and the conversion of a number to text, and the `display` and the dates of a query: `TEXT(350*49799,"[$$-en-US]#.###.##0")` is `$17.429.650` and `"x "&(0.5543*100)&"%"` is `x 55,43%` with `es-CO`, as in LibreOffice. The `locale` option of a single call (`evaluate`, `inspect`, `compile`, a query) still wins.
- Without a locale given, the workbook, an XLSX or an ODS, has the locale of the system (`LC_ALL`, `LC_CTYPE`, then `LANG`, as LibreOffice reads them on Linux; `en-US` when there is none and in WebAssembly), read when it is needed. The language an ODS stores in its default cell style is not read: LibreOffice does not calculate with it. `sheetrs query` and `sheetrs edit` read the `locale` of `[global]` in `sheetrs.toml` (`--config`, or the file of the current directory) between the flag and the system; the linter refuses a value that is not a locale tag. The display of a cell whose format names a language (`[$-C0A]#,##0.00`) uses that language.
- The locale `de-DE` (separators, names of months and days, text dates), with its fixtures. The keywords of its format codes (`TT.MM.JJJJ`, `[ROT]`) are read in English; the difference is a proposal in `docs/approved-differences.md`.
- `sheetrs_io::locale`: `LocaleTag`, `system`, `from_environment` and, with the feature `config`, `from_config`.
- `now` and `seed` fix the volatile functions in `calculate`, in every layer with the same names (issue #106): `Calculation { now, seed }` in Rust, `Book.calculate(..., now=, seed=)` in Python, `calculate(request, { now, seed })` in WebAssembly and `--now`/`--seed` in `sheetrs edit` (through `Book::with_volatile`). `now` is the serial number of `NOW()` (`TODAY()` is its integer part) and `seed` the seed of `RAND()`, as in `sheetc`; without them the clock decides. They also fix the recalculation that the plan runs after an edit that leaves results stale, so a plan gives the same workbook whichever pass calculates.
- The calculation mode of `LibreOffice` is the default of every run, and `calculate_all` emulates `calculateAll()` of its UNO API: `sheetrs edit --calculate-all`, `sheetc calculate --calculate-all`, `sheetc build --calculate-all`, `--calculate-all` of a compiled executable, `Book::with_calculate_all(true)` in Rust, `calculate_all=True` in Python (`save`, `to_bytes`, `explain`, `value_ranges`), `book.calculateAll = true` in WebAssembly (and `sheetrs_set_calculate_all` in the module of a compiled workbook), `calculate_all` in `sheetc.toml` and in the options of `compile`, `Spec::calculate_all` and `Overrides::calculate_all` in the libraries.
- `sheetc build --force-calculate-all` (the key `force_calculate_all`, `Spec::force_calculate_all`): the program stores no cached result for the formulas it keeps, so it calculates all of them in every run and is lighter. It applies to a build only, not to `calculate`.
- A compiled program carries the cached result of the formulas it keeps (`Program::cache`) and a run takes it for every formula that no changed input reaches (`Engine::take_cached`): only the cone of the inputs a request changes is calculated. `--info` lists `calculate_all` and `force_calculate_all` among the build options.
- `find` (`sheetrs query --find --regex`, `Book.find` in Python and WebAssembly) and `replace` (`sheetrs edit --replace --regex`, `Book.replace`) read the anchors `^` and `$` of a regular expression as LibreOffice does in a cell: the start and the end of its text (`$` also before the line terminator that ends it), not of its lines (issue #82). Both read a pattern that can match the empty text (`x*`, `^`, `$`, `a*$`, `(^|$)`) as LibreOffice does: `find` reports the cells that `findAll` reports (the ones `replace` would change), and the replacement is made in the text itself and the search goes on after it, an empty match is replaced only at the very end of the text (`abc` with `$` replaced by `X` is `abcX`; `^` and `x*` change nothing), and no search begins at the end of the text. Compared with `findAll` and `replaceAll` of LibreOffice 26.8 in XLSX and ODS. A search that is still outside the subset of ICU (`\b`, look-around, a repetition of something that can match the empty text) is refused with the list in `sheetrs-query/README.md`.
- The empty search text matches nothing in `find` and in `replace`, in every mode (literal, regex, wildcards), as in LibreOffice: no cell is found or replaced, with no error and before the workbook is read or the pattern compiled (it was the refusal `unsupported search`), in the command line, Rust, Python and WebAssembly.
- `sheetrs_compiler::Only` and `Options::only`/`Spec::only` (the outputs of a recalculation are the formulas inside some cells), `sheetrs_answer::fill_template_to_also` (the results of a program written with the modifications of the same pass, a formula the pass converts becoming its result), and a `CellEdit::Cached` in a cell that `formula_to_value` covers writes the result as a value, in an XLSX and in an ODS.
- Add `hide_rows`, `show_rows`, `hide_columns`, `show_columns`, `hide_sheets` and `show_sheets` to `sheetrs edit`
  (`--hide-rows`, …), the Rust `BookEdit`, the Python `Book` and the WebAssembly `Book`, for XLSX and ODS (#125).
- `Book::recalculation_marked` reads the mark to calculate every formula when a workbook is opened (`fullCalcOnLoad` of an XLSX; an ODS has none) in one place: `sheetc build` and `calculate`, `BookCompile` and `sheetrs edit` take a marked workbook as a run with `calculate_all`, and the workbook a calculation writes leaves without the mark.
- `Options::request_outputs` and `Spec::whole_workbook`: a calculation declares what it is asked and nothing more. With the workbook as the answer (the embedded mode) it declares only its inputs and every formula comes out calculated, the ones the workbook declares no output for included; with no workbook, the `ranges` of the request are the declared outputs of the build when the workbook declares none, and the program keeps only their path.
- `sheetrs-edit/tests/shared_beyond.rs` and its oracle (`make_shared_oracle.py`): the copies of a shared formula that would read outside the sheet, against what LibreOffice shows of the file it saved and opened again.
- The payload of a compiled program (an executable and a WebAssembly module) carries a schema number next to its magic (`bundle::SCHEMA`),
  written by `sheetc` and checked by the runtime before it decodes the program: a payload of another number is refused with a message that
  names both (`payload schema 0 ... reads schema 1`) instead of being decoded as the layout the runtime knows (or reported as "no program
  embedded"). A change of the order or of the type of a field of `Program` or of what it holds bumps it (a test pins the layout).
- `sheetc build` refuses a runtime stub (`--runtime`) and a base module of another payload schema or of another ABI version, naming both; a
  base or a stub that says nothing is refused too. The base module and the stub carry what they read (`SHEETRS_INFO`, the schema marker).
- The module has the export `sheetrs_payload_schema`, added without bumping `sheetrs_abi` (the ABI version is an integer bumped only on an
  incompatible change of the exports or of what they mean; an added export is found by looking for it). The host README says that a module is
  only valid with the `sheetc` that built it.
- Secure mode, off by default: `--secure-mode` of `sheetc` and of `sheetrs edit`, `secure_mode = true` in `sheetc.toml`, `Book::with_secure_mode`, the keyword `secure_mode` of `save`, `to_bytes` and `value_ranges` of the Python `Book`, and the property `secureMode` of the WebAssembly `Book` (and the key `secure_mode` of the options of `compile`, `inspect` and `evaluateFormula`). By default the build refuses a workbook that carries macros, and a call to a function of `LibreOffice` that the engine lacks (`WEBSERVICE`, `FILTERXML`, `DDE`) in a cell the run calculates is an error that names the cause. The refusal is the build's own (`sheetrs_compiler::compile`, `Error::Macros`), so every tool that builds has it, with no policy of the layer: `sheetc build`, `calculate` and `evaluate`, `sheetrs edit` (a run that runs the engine; the Rust, Python and WebAssembly `Book`: `Error::Refused` in `sheetrs-edit`), the answer of a calculation, and the libraries; the error names secure mode. `inspect` and `verify` only read the workbook and do not refuse it. In secure mode the workbook with macros is opened and the run goes on: the cells that call a macro or those functions are error cells (`Err:531` for a macro, `Err:540` for `WEBSERVICE`, `#N/A` for `DDE`, `#NOT_IMPLEMENTED!` for `FILTERXML`, whose result in `LibreOffice` is a value), what reads them is calculated from the error, the rest of the workbook is calculated, and the report holds a warning (`UNSUPPORTED_AS_ERROR` in the diagnostics of `sheetrs edit`, Python and WebAssembly; `warnings` of the build report and the standard error of `sheetc`). Cells that no edit reaches keep the result the file caches with their `*_FROM_CACHE` warning, in both modes (`MACRO_FROM_CACHE` only in secure mode, since a workbook with macros is refused otherwise). The behavior is proposed, not approved, in `docs/approved-differences.md`.
- `now` and `seed` are properties of the workbook, like its locale, and every tool that builds or calculates takes them from it (issue #106): `Book::with_volatile` in Rust (the documented way to initialise them, with `Volatile::or` and `Volatile::configured`), `Book(..., now=, seed=)` and `evaluate(formula, now=, seed=)` in Python, `new Book(bytes, locale, {now, seed})` in WebAssembly, with `book.now` and `book.seed` to read them. The `now` and `seed` of a single call (`calculate`, the options of `inspect`, `compile` and `evaluateFormula`) win over the book's, field by field.
- `now` and `seed` in `[global]` of `sheetrs.toml` are the defaults of `--now` and `--seed` of `sheetrs edit`. The tools of `sheetc` (`build`, `calculate`, `evaluate`, `verify` and the executables) already took `--now`, `--seed` and the keys of `sheetc.toml`; the table of tools and flags is in the README of `sheetrs-compiler`, and the executables, `calculate`, `evaluate` and `verify` have tests on XLSX and ODS now.
- `sheetrs-io/README.md`, *What the writers change of a result when they write it*: a table of what each kind of result (errors, numbers of every size, texts, booleans, dates, times, percentages, currencies, NaN, infinities, empty cells, arrays, in both date systems and both formats) becomes in the file when a writer writes it, against what `LibreOffice` writes and shows after saving and opening again, each row proven by the oracle `sheetrs-edit/tests/assets/writer_results` (`make_oracle.py`, `oracle.json`) and by `sheetrs-edit/tests/writer_results.rs`. A conversion of formulas to values leaves an empty text where the formula gave an error, as `LibreOffice` does (`.uno:ConvertFormulaToValue`, re-read, every kind of error, both formats): that is the reference, not a loss. The differences found (numbers keep all their digits where `LibreOffice` keeps 15, infinities of an XLSX, the empty text constant of an ODS, the text format of constants, the form of the cells) are proposed, not approved, in `docs/approved-differences.md`.

### Changed

- `CONTRIBUTING.md` documents the branches: PRs go to `develop`, `main` receives only `develop` through a release PR, and both are kept aligned.
- `cargo-edit` (`cargo set-version`, the tool of the version step of a release) is installed by `scripts/setup-dev-env.sh` and `scripts/setup-claude-env.sh`.
- A build, a calculation or an edit of a workbook that states no locale no longer assumes `en`: it takes the one of the system (see above). A workbook calculated with a locale other than `en-US` in the environment of the process gives the text of that locale.
- `[$-407]` is read (German); the examples of a language the engine has no names for are now `[$-40C]` (French).
- A range outside the declared outputs is an error that says which outputs are declared when the program is a compiled one (`sheetc calculate` without `-o`, an executable's JSON answer, `Mode::Values`): the new typed `sheetrs_engine::Error::OutsideOutputs` lists them (issue #106). `ranges` is a selection among the declared outputs there; with none declared the outputs stay the formula cells.
- Where `calculate` writes the workbook (the embedded mode: `sheetc calculate -o OUT --json`, an embedded executable or module with `--output OUT --json`, and the `calculate` of `sheetrs edit`, Python and WebAssembly) a range outside the declared outputs, or a constant, is read from the workbook just written, in memory and with the machinery of `query`, in the order asked (`sheetrs_answer`, which every one of those paths calls). It is not calculated again: the inputs are in the workbook, a constant has its value and a formula the outputs left out has the result the template stored (declare it as an output to have it calculated). A text that is no range of the workbook is still an error. No compiler is needed for it, so a WebAssembly module built with `--embed-template` answers it too.
- The default of a build is the load of `LibreOffice`: the constants it folds are the values the workbook stores (a formula that has a result and that no declared input reaches is folded as it), and the formulas it keeps carry the stored result; a formula with no result, a volatile one, and what reads them are calculated, and a workbook that reads cells at run time (`INDIRECT`, `OFFSET`) keeps no cache. With `calculate_all` the build first calculates the whole workbook and folds and stores those results. The inputs a calculation is given are its declared inputs when the workbook declares none, so what they do not reach is not calculated.
- `sheetrs edit` and the `Book` of every binding keep, by default, the results the file caches for the formulas the edit does not reach, and calculate what it reaches and what depends on it; a conversion of formulas to values converts the cached results of the cells nothing reaches and what the engine calculates for the rest, and with `calculate_all` what the formulas calculate. A conversion that needs the engine for a workbook that depends on what it cannot calculate (another workbook, a macro, an extension) is an error that names the cause (or, in secure mode, an error cell and a warning). `sheetc calculate` with nothing given keeps the results the workbook caches too: `--calculate-all` calculates every formula.
- `sheetrs-edit/tests/assets/use_cache/` is `cached/`, and the oracle of the edits holds `reread_default` (what LibreOffice keeps and calculates when it opens, edits without `calculateAll()`, saves and opens the file again) next to `reread` (with `calculateAll()`).
- The engine finds the slot of a cell in a table per sheet and row (flat arrays, with the rows listed for a sheet whose cells are far apart, so that a stray cell in the last row costs a few bytes) instead of a hash map, finds a
  constant by its row inside a decoded block, and keeps the index of a program for the engines that run
  it after the first. On a workbook of 2.4 M formulas a compiled executable answers a request in 1.69 s
  instead of 2.50 s, and `--serve` takes 0.65 s per request instead of 1.5 s, with the same results.
- Writing the workbook of a calculation no longer copies the map of cells to write: a recalculation of
  2.4 M formulas takes 19 % less time and 12 % less peak memory with the same file.
- With `--calculate-all` a conversion of formulas to values converts what the formulas calculate, not what the file caches (`sheetrs edit --formula-to-value`, `Book.formula_to_value` in Rust, Python and WebAssembly). The cells it names are what the engine is asked for (it calculates them and what they read, nothing else of the workbook: `sheetrs_compiler::Only`), and the pass that writes the file writes each as a value in place of the formula, with the deletions, in the same pass: there is no calculation of every formula followed by a pass of its own. LibreOffice converts the cached results of an XLSX, and of an ODS the ones it did not calculate when it loaded the file (`rate*2` cached as 140 was converted as 14 or as 140 depending on the format). By default the conversion reads the results the file holds, as LibreOffice does: the cached ones where the plan reaches nothing, the engine's where it does (`calculation-mode`); `--calculate-all` asks the engine for what it converts. On a workbook of 2.4 M formulas the XLSX that caches nothing is converted faster (no calculation of the whole workbook, `docs/performance.md`), and an ODS, which was streamed from its cached results in 17 MB, now needs the engine (more time and memory, as any run that calculates).
- A range that a deletion leaves with one cell is that cell in the text of an XLSX (`Data!A2`, not `Data!A2:A2`), as LibreOffice saves it, in formulas and in defined names.
- A reference with an end that went (`A1:#REF!`, `Data!A1:#REF!`) is an error of that end in the formula of an XLSX and an ODS (`COUNT` 0, `COUNTA` 1, `SUM` the unknown name of an XLSX or the `#REF!` of an ODS), as LibreOffice reads the file it saved.
- The copies of a shared group of an XLSX that would read outside the sheet are written with a formula of their own and a bare `#REF!` when the run writes the sheet, as LibreOffice saves them; a formula of an XLSX that holds a name LibreOffice cannot resolve (a bare `#REF!`) and caches an error is calculated in the default mode, as LibreOffice does when it opens the file.
- The ODS recalculation on load of formulas whose cached result is a plain number, and `ROW()` of an XLSX, are recorded as approved differences of the default mode; the other classes stay proposed, with their cost.
- The default mode (the cache) calculates what `LibreOffice` calculates when it opens the file, in both formats, and keeps the result the file caches for
  the rest. In an ODS those are the formulas whose cached result is a number, a currency or a date in a cell with no number format (not a
  percentage, a boolean or a time), a cached error, an array formula and a result with no type; what reads them is not calculated, as in `LibreOffice`;
  the writer of an ODS no longer needs the numbers to be wrong to be calculated: the conversion of `book.ods` writes 14 and 8, as `LibreOffice` does (it wrote
  the cached 140 and 99), and the difference that was approved for it is gone. In both formats `HYPERLINK`, every type of `CELL`, `INFO` and `FORMULATEXT` are
  calculated on load, with what reads them, and so are `INDIRECT` and `OFFSET`, which no longer make the workbook calculated whole (the formulas that do not
  depend on them keep their result).
- Hiding or showing rows calculates a `SUBTOTAL` that reads a range with one of them and the formulas of a group (adjacent formulas of a column with
  the same relative references) that read it, as `LibreOffice` does; `AGGREGATE` and a formula alone keep their result.
- `ISFORMULA` and `FORMULATEXT` of a cell that a deletion removed give what `LibreOffice` gives (`FALSE`; `#NAME?` in an XLSX and `#REF!` in an ODS) instead of an
  error.
- `write_to_libreoffice.rs` runs the default mode now against `LibreOffice` for every fixture in both formats (the ODS ones were left out), with the
  new fixtures `classes` (a formula of each class of function) and `indirect`; the probes are in `sheetrs-edit/tests/assets/write_to`.
- The defined names of an ODS are read from the skeleton of `content.xml` (its tables and the blocks of names, searched in the bytes) when they are asked alone,
  which an edit that deletes rows or columns does before its pass.
- `sheetrs edit` on an ODS starts with the calculation that `LibreOffice` runs when it opens one, in the mode of the run: the formulas it calculates on load by default (a cached number in a cell with no format, an error, no result, a few functions), every formula with `--calculate-all`; the roots are the only difference between the modes at the start. The startup is the first pass that runs the engine (a pass of its own when nothing else in the plan needs it, as hiding a column), and the roots are found in the read that compiles the workbook: the scan of `content.xml` that decided before whether to calculate (9.3 s on 2.4 M formulas) is gone. After the startup each operation applies its own rule. An edit that leaves nothing stale now shows what `LibreOffice` calculates on load (`rate*2` 14, `ROW()` 8 where the file caches 140 and 99) and keeps a cached text, and the explanation (`--dry-run`) says the startup first. An XLSX has no startup.
- A conversion of formulas to values is one pass in every mode where the engine runs for it: the engine calculates, in the pass that writes the conversion, what is stale (the cache) or everything (an ODS with `--calculate-all`), and the rest of the scopes is converted with the result the file caches; no pass that writes every result comes first.
- The oracles of the edits compare with what LibreOffice shows when the workbook it leaves after the edit is saved and opened again (re-read), in both formats and for every operation, not with its memory right after the edit (`CONTRIBUTING.md`, *Parity and fidelity*). `sheetrs-edit/tests/assets/write_to/oracle.json` holds `reread` (the default load, the expected values), `cache_differences` (where a hard recalculation of that file shows another value: none), and the memory of LibreOffice only as informational `in_memory_differences`; the scripts that make the expected workbooks of the edits (`gen_book_fixtures.py`, `gen_recalculation_fixtures.py`, `make_shapes_oracle.py`, `compare_structure_with_libreoffice.py`, the replace oracles) save and open the file again before they read it. `write_to` is also checked against writing values (`set_value`, the inputs of a calculation).
- `bundle::read_embedded` returns `Result<Option<Embedded>, PayloadError>` and `bundle::read_payload` returns `Result<Embedded, PayloadError>`.
- The generator of `RAND` mixes the `seed` (the finalizer of SplitMix64) and never starts at zero: distinct seeds now give distinct streams, where an even seed and the next odd one (`seed | 1`) gave the same, and the seed `0` is a seed like the others. The stream for a given seed differs from before. `RAND` of LibreOffice cannot be seeded, so `seed` is an extension of SheetRS with no LibreOffice counterpart (`FIDELITY.md`).
- A reference that went is no longer told from an error written in the formula: there is no "reference that a deletion removed" in the engine: deleted cells and a deleted sheet leave the same text, and `sheetrs_formula::edit::Removal`, `sheetrs_compiler::Removed` and `RemovedAt`, `Spec::removed`, `Spec::removed_at` and `sheetrs_io::write::RemovedRefs` are gone.
- The release workflow creates the `vX.Y.Z` tag itself: when the workspace version reaches `main` and has no tag, the job `plan` tags the pushed commit and the release proceeds as it did for a tag pushed by hand. The dry run (manual run of the workflow) is optional (`CONTRIBUTING.md`, *Releases*).
- `docs/approved-differences.md` lost the entries that the rule of the re-read made unnecessary (the spelling of a reference that went, the deleted-sheet `#REF!`, the whole column over several sheets, the cache that was not kept) and lists, as proposed, the cases where the default mode shows other values than `LibreOffice` after an edit with no `calculateAll()`.
- `ROUND`, `ROUNDUP`, `ROUNDDOWN` and the roundings of number formats (`TEXT`, `DOLLAR`, `BAHTTEXT`) compute the
  15-significant-digit rounding in integer arithmetic instead of writing the number as text: 20 times faster per call
  (295 → 15 ns), a request of a workbook with a `ROUND` per row takes 9-20 % less, and the results are the same bits
  (compared with the text definition over 10^8 values; values out of the range of the integer path still use it).
- The used area of a sheet is found once, in `sheetrs-io`, the same in an XLSX and in an ODS and for every consumer: `Sheet::used_area` is the rectangle of the used cells (a value or a formula; style-only cells, hidden rows and columns and the `<dimension>` element do not count), as the used area of LibreOffice. `Sheet::used_range` (the extent anchored at `A1`, taken from the `<dimension>` in an XLSX and from every cell in an ODS) is replaced by `used_area` and `kept_area` (every cell the file keeps, up to the last hidden row and column), both found by the same accumulator that also serves the streaming readers; the linter's REF304 and REF305 work on the latter, and their results do not change except for a worksheet without `<dimension>`, which they used to skip.
- A workbook that depends on what the engine cannot calculate (another workbook, a macro, an add-in or a function of `LibreOffice` the engine lacks) is run as `LibreOffice` runs it, with no option. A cell that no edit reaches keeps the result the file caches, and the report holds a warning of its kind (`EXTERNAL_FROM_CACHE`, `MACRO_FROM_CACHE`, `EXTENSION_FROM_CACHE`); what reads it is calculated from it. A cell the run calculates (an edit reaches it, or every formula is calculated) is what `LibreOffice` gives: an add-in that is not installed (`_xll.NAME`, `COM.SUN.STAR.SHEET.ADDIN.*`) is `#NAME?`; a macro, `WEBSERVICE`, `FILTERXML` and `DDE` have results only `LibreOffice` gives, so the run is an error that names the cause; a reference to another workbook keeps the stored value of the link. The behavior was observed in `LibreOffice` 26.8 (`sheetrs-compiler/docs/FIDELITY.md`, *What depends on what the engine cannot calculate*; `sheetrs-edit/tests/assets/from_cache/probe.py`). `sheetrs edit` no longer refuses a workbook with macros (`sheetc` does unless `--secure-mode`).
- The writers of XLSX and ODS compress the part they rewrite in another thread while the next bytes are
  produced (a few chunks of memory, none on WebAssembly). A total recalculation of 2.4 M formulas written to a
  workbook takes 16 % less in an XLSX and 11 % less in an ODS. The entries of the archive have the same
  content and order; the compressed bytes can differ by a few from before, and are the same on every run
  and on every target.
- The cells of an XLSX sheet and the rows and cells of the `content.xml` of an ODS are read with a lexer of the suite (`sheetrs_io::xml::Lexer`) instead of the events of `quick-xml`: reading a workbook is faster (`sheetrs stats` of the 2.4 M formulas of the benchmarks, XLSX and ODS, and every tool that reads a workbook with it) at the same memory, and what is read is the same (the tests compare the lexer with `quick-xml` on every XML part of the test workbooks, and the readers with the previous ones on every workbook of the repository). The properties, styles and names parts, the rare elements of a sheet and the writers keep the events of `quick-xml`.
- `parse_cell_ref` no longer allocates a string for each reference it reads.

### Removed

- Build-time constant folding is no longer configurable in any interface (issue #106): `--no-fold` of `sheetc` and the `fold` key of `sheetc.toml` (and of the `options` of the bindings) are gone, and the key is an error like any unknown one. Folding is always on; `Spec::fold` stays as an option of the Rust library for the tests that compare a folded and an unfolded program and for low-level use.
- `--strict` and `--no-strict` of `sheetc` and the key `strict` of `sheetc.toml`: `--secure-mode` (`secure_mode = true`) replaces them, with no compatibility option. `Config::strict` is `Config::secure_mode`; the refusal of a workbook with macros belongs to the build (`compile`), not to a command.
- The options `external_from_cache`, `macro_from_cache` and `extension_from_cache`: the flags `--external-from-cache`, `--macro-from-cache` and `--extension-from-cache` of `sheetrs edit` and `sheetc`, the keys of `[global]` of `sheetrs.toml` and of `sheetc.toml`, `Book::with_from_cache`, `sheetrs_io::FromCache`, `Calculation::from_cache`, the keywords `external_from_cache`, `macro_from_cache` and `extension_from_cache` of the Python `Book` and `calculate`, and the options and properties `externalFromCache`, `macroFromCache` and `extensionFromCache` of the WebAssembly `Book`.

### Fixed

- The smoke tests of `release.yml` read the sheets of the wheel and of the npm package with `stats()`: they used `Book.sheet_names` and `sheetNames`, which 0.4.1 removed, so the release of 0.4.2 stayed a draft.
- The docstring of the `sheetrs` Python module describes `Book.stats()` instead of the removed `sheet_names`, `sheets[name]` and `total_formulas`.
- `CONTRIBUTING.md`: the dry run of `release.yml` is required before a release (its `smoke` job does not run in `ci.yml`), and a tag is created by hand when the fix of a failed release does not touch `Cargo.toml`.

Checked against the files LibreOffice 26.8 saves after the same edits (`sheetrs-edit/tests/write_to_libreoffice.rs`).

The definition of a defined name that went with the sheet reads as `#NAME?` too.
- A reference that is `#REF!` in any spelling (`COUNT(Data!#REF!)` of an XLSX, as Excel writes it) is read by the compiler as the plain error `#REF!` as a whole, so its values are those of the file `LibreOffice` saves and opens again (`COUNT` 0, `COUNTA` 1, `IFERROR` catches it) with no text rewritten in the passes that move nothing (hide, replace, calculate); the formula text of an untouched cell keeps `Data!#REF!`.

  tolerance; `ROUNDUP`/`ROUNDDOWN` of a value with a fractional part and fewer than 12 digits first bring it to 12
  significant digits, as in `ROUNDUP(8.06-8; 2)` = `0.06`; then the number is scaled by `10^digits`, the product is brought
  to 15 digits, the floor or the ceiling is taken and it is scaled back; digits are cut to the fractional bits of the
  number and whole numbers are left alone). A negative number that rounds to nothing is `-0`, and a count of digits
  beyond 32 767 is clamped instead of an error. Over 420 000 values with the three functions (-14 to 14 digits), a probe of
  the forms of the call and 6 669 results of extreme values there is no difference with LibreOffice; before there

- In an ODS, a formula that is a single decimal number (`=1.5`, `=0.25`, `=12345.678`) was read as a reference to a cell (`1.5` as the cell `5` of a sheet `1`), so a conversion of formulas to values that calculates them (`calculate_all`, and the cells an ODS calculates when it is opened) wrote `5`, `25` and `678` for them.
- Deleting a sheet of an XLSX leaves the bare `#REF!` that LibreOffice and Excel write, and the results are what LibreOffice shows when it opens the file it saves after the same edit (`COUNT` 0, `COUNTA` 1, `IFERROR` catches the reference; `SUM` and the rest are `#NAME?` in an XLSX, after a deleted sheet as after deleted cells): `sheetrs-edit/README.md` says what can and cannot be reconciled.

## [0.4.0] — 2026-11-12

The API is **experimental and unstable in every layer** (command line, Rust, Python and WebAssembly): it changes without notice and there is no compatibility promise yet. This release is a restructure of the suite, and most of what follows is breaking with respect to 0.3.2. The reference of behavior is LibreOffice 26.8: XLSX and ODS are read and edited with the same capabilities, each file gives what LibreOffice gives for that file, and the differences that were approved are in `docs/approved-differences.md`. The rules that keep the four layers aligned, and the table of what each operation is called in each of them, are in `docs/api-alignment.md`.

### Changed

- **Breaking, executables:** one executable, `sheetrs`, with the subcommands `query`, `edit`, `lint` and `stats`, replaces `sheetquery`, `sheetedit`, `sheetlint` (and its previous name `sheetcli`) and `sheetstats`; `sheetc` has `build`, `calculate`, `inspect`, `verify` and `evaluate`. The release archives carry `sheetrs`, `sheetc` and `sheetrs-rt`. Each tool crate holds its subcommand behind the `cli` feature; without it the libraries do not depend on `clap`, and neither do the WebAssembly and Python packages.
- **Breaking, flags:** the names are the words of the LibreOffice Calc interface and the same for every tool: the input workbook is `-i/--input FILE` (the positional `FILE` is gone), the output is `-o/--output`, `--in-place` replaces the input through a temporary file and a rename (a failure leaves the original as it was; `sheetrs edit` and `sheetc calculate`), `--delete-sheets`, `--delete-names`, `--delete-rows`, `--delete-columns`, `--formula-to-value`, `--list-sheets` and `--list-names` (of `sheetrs query`). Every edit operation takes the array of its targets, and repeated `--replace`/`--with` pairs make a sweep (paired by position). The default configuration file of `sheetrs lint` is `sheetrs.toml`, and the SARIF tool is `sheetrs lint`.
- **Breaking, calculation:** `sheetc calculate` is one form, `calculate -i FILE|PROGRAM.json [--request JSON|@FILE|-] [--range RANGE]… [-o OUT | --in-place] [--json]`; compiled executables take `--request` and `--range` the same way. The request is `{"inputs", "ranges", "majorDimension"}` and the answer is always `{"valueRanges": [{"range", "name", "values"}]}`, as the batch read of a spreadsheet API answers: with declared outputs and no `ranges`, one entry per output with its `name`, and the values of one cell are `[[value]]`. `calculate(inputs, ranges, major)` is the same in every layer. Recalculating a workbook is `calculate -i FILE -o OUT`; `sheetc verify --reference cache|libreoffice` says what the formulas are compared with. `outputs` is only the declaration of what a compiled program exposes (the `settings` sheet, `--settings-file`, `sheetc.toml`). The standard input is read only when asked for (`--request -`, `--serve`).
- **Breaking, formats:** the format of a workbook (XLSX, XLSM, ODS) is read from its content in every layer and is no longer an argument (the extension is never consulted); a file that is none of them is an unsupported-format error that names what it is.
- **Breaking, dates:** by default a number is the serial the file stores; the `dates` flag (`sheetrs query --dates`, `dates=True` in Python, `dates: true` in WebAssembly and in the JSON query) gives a number whose format is a date or a time as `{"type", "value"}` in ISO 8601. The date system is one of the three of LibreOffice Calc (`DateSystem`: 1899-12-30, 1900-01-01, 1904-01-01); an ODS with another null date is an error that says so, and `--date-system` accepts `1899`, `1900` and `1904`.
- **Breaking, Rust:** `sheetrs_io::Book` is the one interface of the library. It holds where a workbook comes from (`Book::from_file`, `from_bytes`, `from_reader`), its `format()`, what it reads (`workbook`, `analysis_into`, `selection_into`, `date_system`, `defined_names`, `sheet_names`, `external_urls`) and, with the feature `write`, the operations pending on it. Each tool adds its verbs in its own crate as a trait to import: `BookQuery` (`query`, `range`, `find`), `BookEdit` (`delete_sheets`, `delete_names`, `formula_to_value`, `delete_rows`, `delete_columns`, `replace`, `calculate`, `explain`, `value_ranges`, `write`, `write_in_place`, `write_to`), `BookCompile` (`compile`, `calculate`, `inspect`, `verify`, `build_wasm`, `template`), `BookLint::lint` and `BookStats::stats`. The results are typed values (`LintReport`, `Stats`, `ValueRanges`, `Report`, `Diagnostic`, `Inspection`) with explicit conversions (`to_json`, `to_sarif`, `to_text`).
- **Breaking, crates:** the crates are named `sheetrs-<role>`: `sheetrs-core` is `sheetrs-io` (the workbook model, the readers and, behind the feature `write`, the XLSX and ODS writers), the rules and the linter are in `sheetrs-linter`, and there are `sheetrs-protocol` (the typed JSON of the tools), `sheetrs-query`, `sheetrs-stats`, `sheetrs-edit`, `sheetrs-formula`, `sheetrs-engine`, `sheetrs-compiler`, `sheetrs-answer` (writes the answer of a program into the workbook it was made from), `sheetrs-cli`, `sheetrs-wasm`, `sheetrs-rt-wasm` and `sheetrs-py`. `sheetrs-edit` depends on the compiler (the engine is not injected). The libraries report typed errors (`thiserror`; `anyhow` only in the executables); public names lose their `get_` prefix and parse through `FromStr`/`From`; the public types are `Send + Sync`; `#[non_exhaustive]` marks the enums that can grow; modules nobody uses outside their crate are private; every publishable crate has a README, a description, keywords and categories, and all are at version 0.4.0 (`rust-version` 1.99).
- **Breaking, edit plan:** the operations of a `Book` are not a sequence, in every layer: each one is written against the workbook as it is, in its original rows and columns, and the planner decides the order and the passes (cells written and replacements, then the calculation, then one pass with the conversion of formulas to values and the deletions). The order they are pushed in and how they are split into calls change nothing; step by step is one `write` or `save` per step. `--dry-run` (which needs no output) and `explain` show the passes.
- **Recalculation of an edit:** what a deletion or a replacement leaves stale is calculated again by the engine, and the workbook is saved with fresh results and no mark to recalculate it when it is opened; only if the engine cannot calculate it is the workbook marked, and the report says so with the diagnostic `RECALC_NOT_SUPPORTED`. The formulas that are stale are found from the formulas, not from the type of the operation: when none is there is no recalculation pass, a formula that reads a deleted cell is written as `#REF!` without the engine, and the engine calculates the rest. A conversion of formulas to values reads what the workbook has, so a conversion and a deletion in one command are one pass.
- **Python:** the package is one object, `sheetrs.Book`, with `range` (several ranges in one pass), `find`, `lint`, `stats`, `inspect`, `calculate`, the operations that accumulate (`delete_sheets`, `delete_names`, `formula_to_value`, `delete_rows`, `delete_columns`, `replace`) and `save`, the cut that plans and runs them. A query with operations pending raises `PendingOperationsError`; an error cell is a `CellError`. It reads the workbook once when it is made and keeps what it found as properties (`format`, `date_system`, `has_macros`, `sheet_names`, `sheets[name]`, `defined_names`, `stats` and the `total_*`). It takes a path, bytes or a binary stream (`io.BytesIO`) and `save(dest)` writes to a path or a stream; `to_bytes()` gives the bytes. Results are typed (`Stats`, `ValueRanges`, `Report`, `Diagnostic`, `Inspection`, `LintReport`) with `to_dict()`/`to_json()` and, for the lint report, `to_text()` and `to_sarif()`. `sheetrs.evaluate(formula)` and `sheetrs.lint_rules()` are functions of the package. Python 3.13 to 3.15 (SPEC 0), one abi3 wheel per platform.
- **WebAssembly:** the package has one object, `Book`, with the same surface (`lint`, `query`, `range`, `find`, `inspect`, `compile`, the operations of the plan, `save`, `valueRanges`, `explain`, `report`, `dates`, `onDiagnostic`) and typed results with `toJSON()` and `toSarif()`; the free functions are `lintRules`, `evaluateFormula` and `initPanicHook`. The Cargo features `query`, `edit` and `calculate` choose what the module contains.
- **Diagnostics:** structured in every layer: a level (`error`, `warning`, `info`, `debug`), a stable code, the message and its context. The command lines write them on the standard error (`--log-format json` for a record per line, `-q` for the errors only, `-v` and `-vv` for more); Python sends them to the `sheetrs` logger of `logging` and the warnings also to `warnings`; WebAssembly returns them and hands each to `onDiagnostic`.
- **Formulas as LibreOffice shows them:** the readers give a formula in the syntax of its file (Excel's in an XLSX, OpenFormula in an ODS); the linter, the statistics and the compiler work on an analysis form in Excel's notation. `sheetrs query` and `sheetrs edit` see a formula as LibreOffice shows it for that file, and a replacement writes the result back in the syntax of the file.
- **Linter rules:** CPX504–CPX509 report with cell scope; CPX509 counts characters without the namespace prefix of the functions; CALC202 reads the references from the formula AST and has two levels (an error when a cell of the loop holds an error, a warning when only the graph closes it); CALC205 reports only `SUM`, `COUNT`, `COUNTA` and `AVERAGE`; REF307, CPX504, CPX505 and VUL602 read the formula without its literals; REF310 compares value types cell by cell, reports a range only when the cells after it continue the block, and shows the whole block and the suggested range; DATA701, DATA702, DATA703 and DATA704 are corrected (DATA702 does not report formulas), FILE1002 is "Old Spreadsheet", VBA1101 finds ODS macros, REF306 resolves defined names, HID901 tells a very hidden sheet from a hidden one; the violations sort by scope and then rule ID, and the output order is the same on every run. A disabled provider still runs when a rule that depends on it is enabled. The rule reference and the `sheetrs.toml` example are tested against the registry (#50), every rule module documents what it reports and what it does not, and the unused rule stubs are gone. `WalkerRule` hooks take `&mut self` and write the violations into a `&mut Vec<Violation>` sink; the single `WalkerRule` architecture replaces `LinterRule`.
- **Statistics:** `sheetrs stats` groups its output by sheet (per-sheet used cells, errors, empty cells and uncompressed XML size), reports the end of each sheet and its comments, charts and tables, counts only cells with a value or a formula, and counts while it reads, so it does not keep the workbook.
- **Query:** an error cell is `{"error": "#DIV/0!"}`; a formula cell in `General` takes the number format of its result as LibreOffice does; `Find.formatted` searches the text each cell shows; `Find.filtered` leaves out the rows an autofilter hides unless it asks for them; typing into a cell takes the currency symbol and the literal text of the cell format; with `entire_cells` the first match must cover the whole text, and a wildcard `*` takes as little as it can, as LibreOffice does. Notes (`comment`) are read and searched in both formats, and every cell of an array formula reports its formula.
- **Edit, replace:** Find & Replace as LibreOffice does it, over the workbook, a sheet or a range (`--replace`, `--with`, `--scope`, `--regex`, `--wildcards`, `--match-case`, `--entire-cells`, `--in value|formula|comment`, `--formatted`, `--filtered`), in XLSX and ODS: the replacement is entered as if it were typed (a number, a formula or an empty cell) and takes the number format LibreOffice gives it, a formula that refers to another workbook is shown as LibreOffice shows it, and a replacement always reaches the formula cells and makes them constants. A replacement that leaves text that is not a formula is made as LibreOffice makes it (error cell with `Err:5xx`, unknown names in lowercase).
- **Fixtures and tests:** the generators of the binary test fixtures are deterministic and CI checks it; no test judges one format by the other (each file is judged by what LibreOffice gives for it, `sheetrs-io/tests/assets/oracle`); tests are named after the behavior they check, and tests that only verified a design decision were removed.
- **Performance:** the XLSX reader takes 20 % fewer instructions and the ODS reader 36 % fewer (the document is read once); the linter keeps its cells in a compact grid (peak memory of a 6.6-million-cell workbook with every rule from 1.5 GB to 0.6 GB, time halved) and `sheetrs stats` counts while it reads (peak memory of a 39 MB XLSX from 462 MB to 22 MB); REF301 scans each formula once for all the names; `sheetc` lowers formulas on all cores, answers exact `VLOOKUP`/`HLOOKUP` through a hash index, embeds programs in `bincode`, and an executable that exposes every cell starts in milliseconds with a small fixed memory (a 1.2-million-formula workbook builds in 5 s instead of 39 s); a recalculated workbook is deflated at a lower level; a conversion to values of an ODS or an XLSX streams the sheets and keeps at most one row in memory. `docs/performance.md` has the current figures.
- **Dependencies:** `quick-xml` 0.42 and `regex` 1.13 (attribute values follow XML 1.0 normalization; invalid UTF-8 in CDATA is an error), and higher minimum versions of the other dependencies; the minimum Rust version is 1.99; clippy runs with `clippy::all` and `clippy::pedantic` as errors in CI; the rule modules use static `LazyLock<Regex>`; Dependabot groups patch and minor updates and keeps the actions up to date.

### Added

- **`sheetrs query`:** read the cells of an XLSX or an ODS by range, sheet or workbook (`--range`, `--sheet`, `--workbook`, or `--query` with the JSON of `sheetrs-protocol`) with the properties asked for (`value`, `formula`, `number_format`, `display`, `comment`; only those are read), as JSON or one cell per line (`--jsonl`); `display` is the text a person sees, in a locale (`--locale`). `--find` keeps the cells where a text is found as LibreOffice's Find & Replace finds it (literal, regular expression within the subset of ICU that is compared with LibreOffice, or wildcards; match case; entire cells; in the value or in the formula), and `--list-sheets` and `--list-names` give the names of the sheets and the defined names.
- **`sheetrs edit`:** `--formula-to-value` (whole sheets, columns or rows, XLSX and ODS; #11), `--delete-rows` and `--delete-columns` in the coordinates of the input file, and the deletion of sheets and names in both formats. A deletion adjusts the formulas of every sheet, the defined names, merged areas, conditional formats, validations, hyperlinks, filters, notes, manual page breaks, the database and print ranges of an ODS and the shapes and chart series of an XLSX as LibreOffice does: a reference to a deleted cell is `#REF!` and a range shrinks around the deletion; shapes, pictures and charts are placed by the sizes of the rows and columns in the file (in an XLSX the width of a column is in characters, so the position of a shape by columns that differ from the default is an approximation). Peak memory of a conversion alone does not grow with the workbook. Removing every sheet is an error, a result is never written over the input, and a failed write does not remove an output that was there before.
- **`sheetrs lint --format sarif`:** the findings as a SARIF 2.1.0 log (validated against the official schema), besides `human` (the default) and `json`; `sheetrs_linter::output` has the three writers.
- **`sheetc`, the compiler and engine** (formerly the `cosmoscalibur/xlslang` repository): `sheetrs-formula` (a lossless formula AST with a single-pass parser, a canonical printer, reference rewriting and `calc_print`/`calc_read` for LibreOffice's notation), `sheetrs-engine` (a format-independent IR, the function library and a demand-driven evaluator) and `sheetrs-compiler` with `sheetc`: `build` compiles a workbook into a standalone executable (or a WebAssembly module with `--target wasm`), `calculate` compiles and runs in memory, `inspect` reports what a build would find, `verify` recomputes the formulas and compares them with the cache of the file or with LibreOffice, and `evaluate` calculates one formula. Inputs and outputs are declared (the `settings` sheet or `--settings-file`, with metadata) or deduced (the outputs are the formula cells, the inputs the constants a path of dependencies starts from); `--embed-template` makes the workbook its own template, so the executable writes a copy of it with the results (`-o`), answers JSON (`--range`, `--serve`) or both (`--json`); `--meta` and `--info` say what an executable exposes and how it was built; `sheetc.toml` configures the build, with a locale (`en-US`, `en-GB`, `es-ES`, `es-CO`, `es-MX`, a table generated from LibreOffice; `[locale]` can change any field). The compiler warns on manual calculation mode, and `sheetc` stops the build with an error that names what it does not support (`docs/FIDELITY.md#what-stops-a-build`); what depends on an input warns and gives `#NOT_IMPLEMENTED!` when a run meets a case the engine does not reproduce. `INFO("system")`, `INFO("osversion")`, `INFO("release")` and `CELL("filename")` are answered from the machine when the program runs and can be fixed when it is built or run (`--system`, `--osversion`, `--release`, `--directory`, `--filename`, `[host]` in `sheetc.toml`); `--meta` also lists the properties of the document and the defined names it can read, `--version` prints the versions of the compiler and the runtime, and `enable_features` (`LONGTEXT`) joins the `_xlfn._LONGTEXT(…)` text literals that LibreOffice 26.2 wrote.
- **Functions of `sheetc`,** each with oracle rows computed by LibreOffice 26.8 (`FIDELITY.md`): the calendar and series functions, `CELL`, `INFO`, `STYLE`, the complex-number, Bessel and `CONVERT` families, the database functions, depreciation and odd periods, coupons and securities, the statistical distributions and tests, `FORECAST.ETS*`, regressions, frequencies and modes, the dynamic-array functions (`SEQUENCE`, `FILTER`, `SORT`, `UNIQUE`, `TAKE`, `HSTACK`, `TEXTSPLIT`…), the byte-width text functions, `REGEX`, `FOURIER`, the pricing add-in, `LET` and the names of OpenDocument and LibreOffice.
- **Python and WebAssembly:** `sheetrs-py` (PyO3, with type stubs and a pytest suite) and `sheetrs-wasm` (every tool in memory from the bytes of a workbook: no file, process or thread), the web demo in `docs/` (lint, statistics, query, edit, calculate, evaluate and compile to a module that runs in the page) and `scripts/package-wasm.sh`. `sheetc build --target wasm` writes a module of a workbook that needs no imports and no glue; `scripts/build-wasm-rt.sh` builds the two base modules that the release archives carry.
- **Readers:** `Workbook::settings` (the calculation settings a document stores), the named expressions of an ODS, `Workbook::name_conflicts` and the rule REF311 (a defined name defined more than once, with its scopes), `Sheet::state` (`Visible`, `Hidden`, `VeryHidden`), and a selective read (`Selection`, `Window`, `Properties`) that parses only what is asked for: ten rows of a 4-million-cell sheet read in under 10 ms in either format.
- **Documentation and project:** `docs/api-alignment.md`, `docs/performance.md` (the time and memory of every tool on generated workbooks, with the same flows in LibreOffice 26.8.2 and `scripts/bench.py` to measure again), `docs/approved-differences.md`, `docs/references.md`, `docs/environment.md` and `scripts/setup-claude-env.sh` (the environment of Claude Code), the FIDELITY and FUNCTION_NAMES documents of the compiler, installation from GitHub with `uv`, `pip` and `cargo` and the npm tarball of a release.
- **Linter rules:** CALC203 (Double Operator), CALC204 (Approximate Lookup), CALC205 (Double Count), INT401 (Interrupted by Data), INT402 (Interrupted by Empty), INT403 (Interrupted by Other; the three INT rules share one pass), REF309 (Reference to Empty Cell), REF310 (Longer Ref Expected), REF311 (Defined name defined more than once), VUL605 (Legacy Array), VUL606 (Deprecated Function) and DAT706 (Numeric Text Calc); VUL604 detects `LOOKUP`.
- **CI and release:** CI builds, tests and lints the library, builds `sheetrs` and `sheetc` and runs them on a real workbook, checks the WebAssembly package (with a smoke test and the demo in Chromium), checks that the fixtures are deterministic and builds the abi3 wheel for Linux x86_64 and aarch64, tested in Python 3.13, 3.14 and 3.15. A `vX.Y.Z` tag builds the Linux executables, the wheels, the sdist and the npm tarball, smoke-tests them and publishes a release whose notes start with the section of the version in this file; a manual run is a dry run that creates no release. Publishing to crates.io and PyPI is still manual (issue #108). macOS and Windows are issue #99.

### Fixed

- **Behavior as LibreOffice 26.8 gives it, in the engine and the readers:**
  - Booleans: a number with a boolean format is that number (`IF({0;1},TRUE(),5)`); a function that keeps the boolean format of its argument gives the boolean (`VALUE(TRUE())`, `+TRUE()`); `IF` and `CHOOSE` of arrays take the format of the last branch that ran; the missing `else` of an array is read by what takes it; an ODS `office:boolean-value` that is a number is TRUE unless it is zero.
  - Errors: the error code of every function (`Err:502`, `Err:504`, `Err:508`–`Err:511`, `Err:518`, `Err:523`, `Err:539`…) as LibreOffice gives it and carried through the results (`{"error": "#VALUE!", "code": "Err:502"}`), a literal error where a function wants a reference or an array, the number of arguments each function takes and an argument written empty, a bare `#REF!` per file, a sheet that is not in the workbook, and text with an array that does not parse.
  - Arrays and ranges: a range given to a function of a formula that is not an array formula is met by the cell of the formula, in any sheet; an array is taken one element at a time by a function that takes one value; arrays written in a formula may leave elements out; the array of an operator over a range is the whole range; a reference over several sheets (`Data:Wide!A1:A3`) is the same area on every sheet, in the order of the workbook, and goes through `IF` and `CHOOSE`; the database functions take arrays written in the formula.
  - Text and locale: an empty text is read as LibreOffice reads it from each file (blank in an XLSX, an empty text in an ODS with a paragraph); the text format is never taken from a cell, and an aggregate takes the format of the first argument that holds a number; text is ordered by ICU4X's collator and case is mapped by its case mapper (72,771 pairs compared in seven languages); `CHAR`, `CODE`, `MATCH`, `LOOKUP`, `COUNTIF`, dates up to the year 32767 and regular expressions (the compared subset of ICU) follow LibreOffice.
  - Display: the text a cell shows for a date, a time or an elapsed time is what LibreOffice writes (Julian calendar before 1582-10-15, `#FMT` outside the range of the formatter, `[hh]`/`[mm]`/`[ss]`, the fractions of a second), and `General` is written in scientific notation below `1E-4`; an ODS `office:date-value` before the year 1 is a date.
  - `NORMSINV(0.5)` and every function that reached `erf` at minus zero never returned; `ERF` and `ERFC` follow the algorithm of the C library; `RANDBETWEEN` rounds its limits away from zero; `MATCH`, `VLOOKUP`, `HLOOKUP` and `XLOOKUP` with a text criterion find the number the text shows; the hasher of the engine no longer collides on whole numbers stored as `f64` (a 600,000-row `VLOOKUP` build took 56 s and takes 6 s).
- **ODS:**
  - Dates are numbered from the document's `table:null-date`, and time cells are fractions of a day.
  - A cell with content and no style takes the default style of its row or column; the number formats of every family of data style are read; an error only LibreOffice has keeps its code (`Err:522`); negative times are numbers; a numeric cell in a cell formatted as Text is a number.
  - Formulas: `[#REF!]` and a reference across sheets (`[$T.A2:$V.A4]`) are read as an XLSX writes them, a reference without `$` or with a quoted sheet name is normalized to the XLSX formula, the row separator `|` of an array constant is read, text inside a formula's string literal is not rewritten as a reference, and the comment of a cell is not read as its value; runs of spaces, tabs and line breaks in cell text are kept.
  - Names and settings: a defined name written after the last table no longer takes the table as its scope, and the last-modified date saved by LibreOffice is read.
  - Parsing sheets that end in large repeated row blocks is no longer slow, and hidden rows and columns are stored as ranges.
- **XLSX:**
  - Entity and character references are no longer dropped from element text (#48; `IF(A1<0,"Y","N")` was read as `IF(A10,Y,N)`), and text cells keep their leading and trailing spaces.
  - The cached string result of a formula that reads as a number (`"007"`) is text; an error constant (`t="e"`) is not an empty cell; a range in a cell that holds `#VALUE!` is `#VALUE!`; sheets with an absolute relationship target are found; hidden rows written as `<row hidden="1"/>` are detected.
  - Shared formulas shift whole columns and rows and leave alone what is not a cell (`TOTALSALES2024`, `LOG10(`), and one that would read outside the sheet is `Sheet!#REF!`; the writer no longer writes a second `calcPr`.
- **`sheetrs edit`:**
  - `--delete-sheets` turns the references to the removed sheets into `#REF!`, and `--delete-names` leaves the name unknown in the names that used it; sheets and names whose names contain XML entities (`R&D`) are no longer ignored; the same command gives the same workbook (formula edits were applied in hash order).
  - A conversion to values leaves an empty text where the formula gave an error (as Formula to Value does); a conversion after a deletion converts the results the engine calculates, not the stale ones the file cached; a conversion of an ODS formula that carried a shape or a note stays a formula; an ODS saved by the previous step and the same plan in one pass give the same workbook.
  - A manual page break left before the first row or column is not written, since LibreOffice reads none from a file.
- **`sheetrs lint`:** the output order is the same on every run (#33); REF310 reports the same set of violations on every run and no longer skips the later ranges of a formula (#34); disabling CALC202, CPX504 or ERR102 no longer changes the results of the rules that depend on them (#53); CALC205 no longer overflows a column index on arguments that are not ranges (#69) or reports cross-sheet references as double counts; VUL604 is not triggered by `XLOOKUP`; DATA702 does not report the text a formula returns; the text report no longer prints the `Sheet:` header twice (#70) and lists the cells in row and column order; a configuration naming a rule or category the linter does not know is rejected when parsed in every interface; ERR102 does not count a saved `#NAME?` for a function with the `_xlfn.` prefix; a cell error value that could not be parsed is not reported as an "unknown rule ID"; REF301 documents that it also reports an unused name whose reference is broken.
- **WebAssembly:** `cargo doc` with warnings as errors passes; the writer of a native executable no longer calls `drop` on a file without a destructor on that target; the compiler reads the clock only when `SHEETC_TRACE` is set (reading it panics there).
