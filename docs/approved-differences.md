# Approved differences from LibreOffice

SheetRS gives the result LibreOffice gives. A difference exists only if the maintainer approved it,
and it is recorded here with where it is described. Anything else that differs is a bug or a pending
decision, never a documented feature.

| Difference | Where | Why |
| ---------- | ----- | --- |
| A query has no direction (rows or columns): the cells come in the order of the sheet | `sheetrs-query/README.md` | Scope of the tool |
| Some mathematical functions are computed with `libm` and may differ in the last digits from LibreOffice's | `sheetrs-compiler/docs/FIDELITY.md` | Technical |
| `LONGTEXT` (the pieces of a text over 255 characters) is a feature that is enabled on request | `sheetrs-compiler/README.md` | Scope |
| `include_formulas` is `false` by default in a query: a search by value looks at what was typed, not at the results of formulas | `sheetrs-query/README.md` | Usability |
| A cached error of an XLSX is read as the file keeps it (`#VALUE!`), where LibreOffice recalculates the cells with an error when it opens the file and shows its own code (`Err:502`, `Err:522`). To have LibreOffice's errors, recalculate the workbook first (see the recipe) and read the result | `sheetrs-query/README.md`, `docs/recipes.md` | Reading does not calculate |
| Regular expressions outside the subset of ICU that was compared with LibreOffice are refused in a search and in a replacement, instead of giving another result (issue #82 extends the subset). The anchors `^` and `$` are in the subset of a search (`find`, `sheetrs query --find`) and of a replacement (`replace`, `sheetrs edit --replace`), as LibreOffice reads them in a cell (compared in both formats); they stay outside the subset of the functions of the engine (`REGEX`, `COUNTIF`...), whose semantics are another matter. A pattern that can match the empty text (`x*`, `^`, `$`, `a*$`, `(^|$)`) is read by both, as `findAll` and `replaceAll` read it (compared in both formats); the empty search text matches nothing in both, as in LibreOffice (no error, nothing read). What stays refused is listed in `sheetrs-query/README.md` | `sheetrs-query/README.md`, `sheetrs-edit/README.md` | Scope |
| Only the three date systems of the LibreOffice Calc interface are supported: 1899-12-30 (the default, and the 1900 system of an XLSX), 1900-01-01 (StarCalc 1.0) and 1904-01-01. LibreOffice can store another null date (its API, a crafted ODS `table:null-date`); SheetRS gives an error that names the date, when the workbook is read, in every tool, instead of numbering the dates from it | `sheetrs-compiler/docs/FIDELITY.md` (Date system), `sheetrs-io` (`Error::UnsupportedDateSystem`) | Scope: an arbitrary null date is not reachable from the interface and no tool writes it |
| `FORECAST.ETS` and its variants, with an error written in an option or next to a series of a single value: LibreOffice reads the error as a number (the payload of the NaN) and uses it without checking it (`FORECAST.ETS(7,{1;3;2;5;4;6},{1;2;3;4;5;6},#NAME?)` is 9.22337203685478E+18, the largest 64-bit integer), SheetRS answers the error | `sheetrs-compiler/docs/FIDELITY.md` | An unchecked conversion of LibreOffice, not a rule; the error is the useful answer |
| `SUM(Data!A1:Wide!A1048576)` in an XLSX (a whole column over two sheets): the headless LibreOffice that recalculates the file gives `#NAME?`; SheetRS reads the form and adds the cells, as Excel does and as LibreOffice itself writes the form when it saves | `sheetrs-compiler/docs/FIDELITY.md` | The form is written by LibreOffice and by Excel; the `#NAME?` is a limit of the headless mode |
| Only the A1 notation of references is supported. LibreOffice can read and show references in R1C1 notation (*Tools ▸ Options ▸ Calc ▸ Formula*, and in the API); SheetRS has no R1C1 grammar: a range written in R1C1 (`T!R1C1:R2C2`) is refused in every tool with "is not a range", and the formulas of a file are always read in the notation the format stores (A1) | `docs/coding-patterns.md` (Formula Normalization) | Scope: R1C1 is not usual and no file stores it |
| The result a file caches in a formula cell is not kept as a goal: after a deletion, a removal or a replacement the engine calculates every formula and the cell holds the value the formula gives now, which can differ from the one LibreOffice cached if the engine and LibreOffice differ on that formula | `CONTRIBUTING.md` (Parity and fidelity), `sheetrs-edit/README.md` | The real value of the cell prevails over the cache (`--use-cache`, `use_cache`, `useCache` keep it for the formulas an edit does not reach, when the caller asks), which a generated workbook or an incompatible version may not have made reliable |
| A replacement by a regular expression that skipped an empty match before a character outside the Basic Multilingual Plane and can then match half of it (`^|.` on a cell with an emoji): LibreOffice writes a text with a lone surrogate (not valid in UTF-16 text as a character, and not representable in UTF-8 or in XML; it brought a LibreOffice server down in the probe); SheetRS goes on after the whole character | `sheetrs-edit/README.md` | The result of LibreOffice is not a valid text: a Rust `String` and the XML of both formats cannot hold it |
| A reference that an edit removed is spelled as the files of LibreOffice and Excel spell it, not as LibreOffice shows it in memory. After deleting rows or columns, LibreOffice's API gives `=$Data.A#REF!*2` (a token with no cell: `$#REF!.A3` for a sheet that went); the file it saves says `[#REF!]*2` (ODS) and `#REF!*2` (XLSX), and SheetRS writes `[#REF!]*2` (the same text) in an ODS and `Data!#REF!*2` in an XLSX (`#REF!*2` for a sheet that went, as LibreOffice and Excel write it). The formula text of the cell that `sheetrs query` or a lint rule reads is then `COUNT(#REF!)` or `COUNT(Data!#REF!)`, not LibreOffice's in-memory text | `sheetrs-edit/README.md` (Delete rows and columns), `sheetrs-compiler/docs/FIDELITY.md` (References that go) | The spelling of LibreOffice exists only in memory: no file of either format holds it (LibreOffice itself saves `#REF!`), `Data!A#REF!` is not a formula Excel reads, and writing it would need a new grammar in the readers, the writers, the editor of formulas and the compiler. What changes the result of the formula is not the spelling but whether the reference went or was written, and the recalculation of an edit reads it as LibreOffice's edit does (the values are those of LibreOffice in the 68 edits of the oracle). An ODS written by SheetRS reads back in LibreOffice exactly as the one LibreOffice saves (0 differences in formulas and values over the oracle, `reread_differences`); an XLSX reads back better than LibreOffice's own (`Data!#REF!` is the reference that went there: `COUNT` is `#REF!` and not 0, `SUM` is `#REF!` and not `#NAME?`), except `ROWS` of a range that went whole (1 when LibreOffice reads `ROWS(Data!#REF!)`, `#REF!` in the edit and in the cache) and after a deleted sheet, where both files hold the bare `#REF!` that LibreOffice reads as an unknown name. A search or a replacement in the text of a formula reads the text of the file, which holds `#REF!` as the files of both programs do; lint rules (ERR101, ERR102, ERR103, REF301) look for `#REF!` in the text, which every spelling holds. Impact analysed and approved by the maintainer as the fallback of the decision on the differences of `write_to` against LibreOffice |

Adding a line requires the maintainer's approval, in the pull request or the issue it came from.

## Proposed, not approved

These differences from LibreOffice exist in the code and wait for the maintainer's decision; nothing
here is approved until it moves to the table above.

| Difference | Where | Why it is proposed |
| ---------- | ----- | ------------------ |
| `de-DE`: the keywords of a format code are read in English (`dd.mm.yyyy`, `[Red]`, `[$-409]dddd d`), where a German LibreOffice reads `TT.MM.JJJJ` and `[ROT]` and keeps `d`, `y`, `[Red]` as text or an error (`dd.mm.yyyy` is `dd.03.yyyy`, a code with `[Red]` is `Err:502`). 19 rows of `semantics_de-DE.*` | `sheetrs-compiler/docs/FIDELITY.md` (Locale support), `sheetrs-compiler/tests/semantics/oracle.rs` (`GERMAN_FORMAT_CODES`) | Needs the table of keywords of each locale (`FormatElementsKeywords`), which the engine does not have; the separators, names and dates of `de-DE` match |
