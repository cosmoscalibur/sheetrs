### Changed

- `sheetc`: exact `VLOOKUP`/`HLOOKUP` over a big range go through a hash index of its key column and compare text without allocating; programs are embedded in `bincode` instead of JSON. On a 1.2 M-formula synthetic workbook the build takes 16 s instead of 39 s and the executable is 100 MB instead of 234 MB; a 500 k-formula real workbook starts in 0.25 s instead of 0.57 s and its executable halves (104 MB to 50 MB).
- `sheetc`: formulas are lowered on all cores and the range nodes of the dependency graph are no longer copied. Delgado build 9.6 s → 8.3 s; the 1.2 M-formula workbook builds in 11.5 s (was 39 s) and `verify` takes 8 s (was 36 s).
- `sheetc verify --recalc` compares with a full LibreOffice recalculation of the file (`$SOFFICE` or `soffice`, under the build locale) instead of the file's cached values. LibreOffice reads a bare `#REF!` of an XLSX formula as an unknown name, which the engine now reproduces.

- `scripts/measure_perf.py` measures the full matrix (compiler build with its stages, engine start-up and execution; wall, user and system time, peak memory, sizes) for the small, Delgado and large workbooks; `SHEETC_TRACE` also prints the read, compile and write stages of `build`.
- `_xlfn._longtext(…)`, which LibreOffice 26.2 wrote around text literals over 255 characters and 26.8 reads as `#NAME?`, evaluates to `#NAME?` and is listed per cell in the build diagnostics.

- The hasher of the engine's maps mixes the high bits down, so keys that are whole numbers stored as `f64` (the index of a lookup column of numbers) no longer collide: building a 600,000-row `VLOOKUP` took 56 s and takes 6 s.

- `sheetc` reads the workbook on its own path: the XLSX and ODS readers hand each cell to a `CellSink` as it parses it, and the compiler stores them in a dense row-indexed `CellStore` instead of a hash map of the reader's `Workbook`. The linter keeps the reader's map. A test (`reading_straight_into_the_model_matches_reading_the_workbook`) compares every cell of both paths, on the fixtures and, with `SHEETC_PARITY_PRODUCTION=1`, on the production workbooks. Delgado as ODS (7.5 MB) builds in 5.1 s instead of 6.5 s (reading 1.5 s instead of 2.4 s), peak memory 849 MB instead of 975 MB.

- An executable built with `outputs = any` keeps its constants in fixed-size blocks and decodes a block when a request first reads a cell of it, so start-up and memory no longer grow with the workbook. On the 49 MB, 600,005-formula workbook the executable starts and answers a small request in 2 ms with 12 MB (0.65 s and 541 MB before, 1.7 s and 693 MB for the request) and is 140 MB instead of 179 MB; reading all 4.8 M cells of its data sheet takes 2.1 s (3.4 s before).
- `SUM`, `AVERAGE` and the other functions that gather numbers read a small range without building an array (below `SMALL_RANGE` cells in `engine.rs`), and the build sizes its folded-values map up front.

- `sheetc` build, found with flamegraphs (`--features profile`): the fold stage moves the formulas to the engine and takes them back instead of copying each one (the copies were 22 % of the Delgado build's CPU samples); a one-cell dependency is looked up directly instead of through a shared rectangle; the folded values are a vector by node instead of a hash map; and `CellStore::insert` appends without searching when a reader delivers cells in row order. `same_name` (sheet names, case-insensitive) compares ASCII names without the Unicode lower-case mapping: it was 16 % of the Delgado build. The programs are byte-identical to those of the previous build. Median of five alternated builds: Delgado 4.8 s → 4.1 s, 1.2 M-formula workbook 6.3 s → 5.2 s, 49 MB workbook 9.3 s → 8.4 s (declared outputs 6.2 s → 5.6 s).
- `scripts/measure_perf.py` stops when a build or request fails instead of reporting zeros, uses the real range of the small workbook (`Loan!B1:B8`; `Summary!A1:C5` does not exist in it and its request failed silently) and prints the engine rows in milliseconds.

- `UPPER` and the text comparisons that ignore case map accented text letter by letter with the standard library when each letter has a one-letter uppercase, and ask ICU4X only for the others (`ß`, ligatures, characters after the plane 0). The Delgado request, which had become 12 % slower with ICU4X (0.36 s → 0.41 s, medians of 31 alternated runs, noise ±1.5 %), is back at 0.365 s; its flamegraph showed the cost in `casemap::upper`. A test compares both paths for every character of the plane 0.
