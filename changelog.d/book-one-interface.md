### Changed

- **Breaking:** `sheetrs_io::Book` is the one interface of the Rust layer, and `Source` and `Editor` do not exist. A `Book` holds where the workbook comes from (`Book::from_file`, `Book::from_bytes`, `Book::from_reader`), its `format()` and, with the feature `write`, the operations pending on it (`push`, `operations`, `clear_operations`, the seam the tools use). It reads (`workbook`, `workbook_into`, `analysis_into`, `selection_into`, `date_system`, `defined_names`, `external_urls`); the free `read_*` functions of the reader are no longer public. Each tool adds its verbs to it in its own crate as a trait to import: `sheetrs_query::BookQuery::query`, `sheetrs_edit::BookEdit` (`delete_rows`, `replace`, `calculate(Calculation)`, `write`, `write_in_place`, `write_to`, `explain`), `sheetrs_compiler::memory::BookCompile` (`compile`, `calculate`, `inspect`, `verify`, `build_wasm`, `template`), `sheetrs_linter::BookLint::lint` and `sheetrs_stats::BookStats::stats`. `sheetrs_query::run`, `sheetrs_stats::collect`, `memory::{build, calculate, inspect, verify, build_wasm, template_of}`, `modify_workbook_source*` and `Editor::keep_outputs` are replaced by them (`Calculation::answer` keeps the outputs of a calculation). The operations are plain data in `sheetrs_io::write` (`Operation`, `ReplaceSpec`, `Calculation`).
- **Breaking:** the operations of a `Book` are **not a sequence**, in every layer (the command line, Rust, Python and WebAssembly): each one is written against the workbook as it is, and the planner (functions of `sheetrs-edit` that take the `Book`) decides the order they run in: cells written and replacements, then the calculation, then one pass with the conversion of formulas to values and the deletions of rows, columns, names and sheets, in the rows and columns of the workbook. The order they are pushed in, and how they are split into calls, changes nothing (the files are byte for byte the same): `delete_rows("S!3")` twice is the row 3 once, and a conversion pushed with a deletion reads the values the workbook has. The operations of one kind keep their order (a sweep of replacements). Step by step is one `write` or `save` per step, the saved workbook being the input of the next. An operation on a sheet that is also deleted is no longer an error (`Error::DeletedSheet` and `Python`'s `InvalidRangeError` from `explain()` for it are gone), and the outputs of a calculation are asked for in the `Calculation`, not in the editor (`Error::NoCalculation` is only that of `Report::write_json` with none kept).
- **Breaking:** the mark to recalculate (`fullCalcOnLoad`, or the results dropped in an ODS) is a consequence of the engine failing and is never decided before it runs. What a deletion or a replacement leaves stale is calculated again by the engine as the last pass of the run (the planner adds it), and the workbook is saved with fresh results and no mark; only if the engine cannot calculate the workbook is it marked, and the `Report` says why (a diagnostic with the code `RECALC_NOT_SUPPORTED`). `BookEdit::marks_recalculation` is gone, the planner no longer sets or clears the mark in any pass (`clear_recalculation_mark` is only used on what the engine returns), and the output of a run is never the input file (checked before any pass writes).
- `BookQuery` has `range(ranges, &RangeOptions)` (one `Block` per range: the cells of `Data!A1:C10`, an open range or a defined name, by rows or columns, with the properties asked for) and `find(&Find, &FindOptions)` (the cells that match, by rows or columns), as `Book.range` and `Book.find` of Python give them (Python now calls them), besides the general `query(&Query)` that the command line (`sheetrs query --range`, `--find`) and WebAssembly (`query_workbook`) take. `Book::sheet_names()` reads the names of the sheets.
- Deleting rows or columns places the shapes, pictures and charts as LibreOffice does, by the sizes of the rows and columns that are in the file, and no deletion is refused for a shape any more (`Error::ShapeDependsOnSizes` is gone): a shape wholly inside the band is deleted with it, one whose anchor cell goes keeps that index, a rectangle whose ends cross has them put in order, and the size comes from the end cell, or is kept (scaled by the size of the cell) when both ends are in one cell. Checked against LibreOffice 26.8 on every band of rows and columns up to five wide of the fixtures, in XLSX and ODS (`sheetrs-io/tests/assets/oracle/shapes_delete.json`). In an XLSX the width of a column is in characters, so the position of a shape by columns that differ from the default is an approximation.
- The XLSX writer no longer writes a second `calcPr` when the mark is taken off and put on in one pass, and an XLSX error cell that the engine calculates from a formula LibreOffice cannot read is written as LibreOffice writes it (`Err:520` is `#N/A`).
- Tests whose names said nothing about what they check (`the_options_say_what_they_are_for`, `calc_command`, `*_basic`, `literals`, `references`, `dates`, `numbers`, `parsing`, ...) are renamed after the behavior under test (29 of them).
