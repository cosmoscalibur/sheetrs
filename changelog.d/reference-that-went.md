### Fixed

- After an edit that deletes rows, columns or sheets a reference that went is the `#REF!` that the files of LibreOffice and Excel hold (`[#REF!]` in an ODS, the bare `#REF!` in an XLSX, for deleted cells and for a deleted sheet), and the engine reads it as LibreOffice shows it when the file is saved and opened again: `COUNT` 0, `COUNTA` 1, `COUNT(ref;5)` 1, `IFERROR(ref;7)` 7, `ISERROR` true, `SUM`, `AVERAGE`, `MAX`... `#REF!` in an ODS and `#NAME?` in an XLSX (after a deleted sheet `#REF!`, an approved difference), `COUNTBLANK` and `SUMIF` `Err:504` in an ODS. The memory of LibreOffice right after the edit (where `COUNT` of it is `#REF!` and `IFERROR` does not catch it) is not a reference: the same workbook, saved and opened again, shows the values above. A qualified `Data!#REF!` of the input is written bare when a deletion rewrites its formula. Checked against the files LibreOffice 26.8 saves after the same edits (`sheetrs-edit/tests/write_to_libreoffice.rs`).
