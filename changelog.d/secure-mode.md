### Added

- Secure mode, off by default: `--secure-mode` of `sheetc` and of `sheetrs edit`, `secure_mode = true` in `sheetc.toml`, `Book::with_secure_mode`, the keyword `secure_mode` of `save`, `to_bytes` and `value_ranges` of the Python `Book`, and the property `secureMode` of the WebAssembly `Book` (and the key `secure_mode` of the options of `compile`, `inspect` and `evaluateFormula`). By default the build refuses a workbook that carries macros, and a call to a function of `LibreOffice` that the engine lacks (`WEBSERVICE`, `FILTERXML`, `DDE`) in a cell the run calculates is an error that names the cause. The refusal is the build's own (`sheetrs_compiler::compile`, `Error::Macros`), so every tool that builds has it, with no policy of the layer: `sheetc build`, `calculate` and `evaluate`, `sheetrs edit` (a run that runs the engine; the Rust, Python and WebAssembly `Book`: `Error::Refused` in `sheetrs-edit`), the answer of a calculation, and the libraries; the error names secure mode. `inspect` and `verify` only read the workbook and do not refuse it. In secure mode the workbook with macros is opened and the run goes on: the cells that call a macro or those functions are error cells (`Err:531` for a macro, `Err:540` for `WEBSERVICE`, `#N/A` for `DDE`, `#NOT_IMPLEMENTED!` for `FILTERXML`, whose result in `LibreOffice` is a value), what reads them is calculated from the error, the rest of the workbook is calculated, and the report holds a warning (`UNSUPPORTED_AS_ERROR` in the diagnostics of `sheetrs edit`, Python and WebAssembly; `warnings` of the build report and the standard error of `sheetc`). Cells that no edit reaches keep the result the file caches with their `*_FROM_CACHE` warning, in both modes (`MACRO_FROM_CACHE` only in secure mode, since a workbook with macros is refused otherwise). The behavior is proposed, not approved, in `docs/approved-differences.md`.

### Removed

- `--strict` and `--no-strict` of `sheetc` and the key `strict` of `sheetc.toml`: `--secure-mode` (`secure_mode = true`) replaces them, with no compatibility option. `Config::strict` is `Config::secure_mode`; the refusal of a workbook with macros belongs to the build (`compile`), not to a command.
