### Added

- **Structured diagnostics** in every layer. `sheetrs_protocol::Diagnostic` is a record of what a run reports besides its result: a `Level` (`error`, `warning`, `info`, `debug`), a stable `code` (`RECALC_NOT_SUPPORTED` for a calculation the engine cannot do), the `message` and the `context` fields it was made from (`operation`, `reason`). The command lines write them on the standard error with `sheetrs_protocol::Logger`: text by default and `--log-format json` for a JSON record per line, errors and warnings by default, `-q` for the errors only, `-v` for what the command did (what `sheetc` wrote, the summary of a build) and `-vv` for the detail; `sheetrs` has the three flags for all its subcommands and `sheetc` for its commands. Python sends each to the `sheetrs` logger of `logging` (the code and the fields in `extra`) and the warnings also to `warnings.warn`; WebAssembly returns them in `diagnostics` and hands each to an optional `onDiagnostic` function (`edit_workbook`, `compile_workbook`).
- **Python: what the opening found out.** A `Book` reads the workbook once when it is made and keeps the counts: `format`, `date_system` (the `datetime.date` of serial 0), `has_macros`, `sheet_names`, `sheets[name]` (a `Sheet` with `name`, `used_range`, `state` and the counts), `defined_names`, `stats` and the eleven `total_*`. `sheetrs_stats::WorkbookStats` and `SheetStats` hold the macros, the defined names and the state of each sheet (not in `sheetrs stats --format json`, which is unchanged), and are `Clone`, `Default` and `PartialEq`.
- **Python: streams.** `Book` takes a binary stream (`io.BytesIO`, a file opened with `"rb"`) or a `bytearray` as well as a path or bytes; `save(dest)` writes to a path or a stream, `save()` rewrites the stream the `Book` was made from, and `json=` takes a path or a stream.
- **Python: `Book.inspect()`**, `sheetc inspect` as an `Inspection` with `FunctionUse` items.

### Changed

- **Breaking:** the results are typed values with explicit conversions, never an implicit `dict`: in Python `Stats`, `Sheet`, `Outputs`, `Report`, `Diagnostic`, `Inspection` and `LintReport` have `to_dict()` and `to_json()` (and the lint report `to_text()` and `to_sarif()`). `Book.to_dict()` is `Book.outputs()`, an `Outputs` (a mapping from the name of each output to a `Block`); `Book.report` is a `Report` (`replaced`, `written`, `skipped`, `diagnostics`; no `warnings` list); `Book.lint(config)` returns a `LintReport` and has no `format` or `file` argument (`to_json(file=None)`, `to_sarif(file=None)`); `Book.stats` is a property and `Book.defined_names` a property. Opening a workbook whose date system is not one of the three raises `UnsupportedDateSystemError` at once, since the opening reads it.
- **Breaking:** `sheetrs_edit::Warning` is gone: `Report::warnings` is `Report::diagnostics`, a list of `sheetrs_protocol::Diagnostic` (the code is `sheetrs_edit::RECALC_NOT_SUPPORTED`), and `Report::outputs` is a `sheetrs_protocol::Outputs` (`Response` of the protocol crate, renamed, with `to_json`, `write_json` and `to_entries`). `edit_workbook` of WebAssembly answers `diagnostics` (records) where it answered `warnings` (texts). `sheetrs edit` and `sheetc` write their messages through the logger: a warning is `warning: …` as before; what `sheetc` wrote (`wrote OUT`, the summary of a build) is written with `-v`.
- **Breaking:** `sheetrs_protocol::CellRecord` shares the sheet of its cells (`sheet: Arc<str>`, one copy per sheet) and works out the A1 text from `row` and `col` (`cell()`, no field): its JSON is the same (`sheet`, `cell`, `row`, `col`, …). The matches of Python's `find` do the same.
- `sheetrs_linter::BookLint::lint` gives a `LintReport` (the violations, their `records()`, and the report as text, JSON and SARIF: `to_text`, `to_json`, `to_sarif`, `write`) and no longer a `Vec<Violation>` (`LintReport::violations()` is the slice); Python's `LintReport` wraps it.
