### Fixed

- The element that a missing `else` of an `IF` gives (`IF({0;1},1)`) is read as `LibreOffice` reads it, by what takes it (`scripts/probe_marker.py` asks every function that takes one value): the number 0 for a number (`+`, `ABS`, a condition), the text `FALSE` for a text (`LEN` is 5, `&`, `UPPER`, `EXACT`), an empty text for `VALUE` (`Err:502`) and for the criteria `""`, and empty in a comparison; the cell that holds the array of `TAKE`, `SORT`, `UNIQUE`… shows an empty text and `TRANSPOSE` a 0; a concatenation between two arrays reads it as an empty text; `VLOOKUP("",…)` does not find it; `COUNTIF`/`SUMIF` criteria count it as the number 0.
- What `IF`, `CHOOSE`, `IFERROR`, `IFNA` and `INDEX` (row or column 0) give is not taken element by element by a function that takes one value outside array evaluation: it gets the first element (`SUM(ABS(IF({1;1},2,3)))` is 2), as in `LibreOffice` (`scripts/probe_jump.py`).
- `COUNTIF`, `SUMIF` and the like over an array written in the formula match nothing for the criteria `=` and `<>` alone; the text `TRUE` or `FALSE` as a criterion is also the number 1 or 0; `ISEVEN` and `ISODD` of a text and `ROW` and `COLUMN` of an array are `Err:504`; `VALUE("TRUE")` is 1.
