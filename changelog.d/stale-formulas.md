### Changed

- The planner decides the recalculation after deleting rows, columns or sheets from the formulas, not from the type of the operation (issue #102): the formulas that read what the deletion changes (a deleted cell, a range that loses cells, a deleted sheet, or a formula that reads such a formula, or a function that depends on positions) are the stale ones. When none is, there is no recalculation pass (so a conversion of every formula and the deletion are one pass, and a sheet that nothing reads is deleted in one); the ones whose value is `#REF!` by a deleted reference are written with it by a last pass that runs no engine; the engine calculates the rest, and only those formulas are written with a new result. `--dry-run` and `BookEdit::explain` read the workbook to say which. A defined name that points to cells no deleted row or column touches (`Data!$I$1` with `Data!10:20` deleted) no longer sends the plan to the whole-workbook path. What cannot be told (a defined name that points into what is deleted or is not a plain reference, cycles, formulas the compiler keeps as cached values) is left to the engine over the workbook, as before.
- What a cell the plan leaves alone gives is read from the file (the cached results are valid): a number, a boolean or an empty cell is never an error, so a formula that mixes one with a deleted reference is given `#REF!` with no engine (`D10*$B$2/12` with `B2` deleted); the cells that cache a text or an error, and array formulas, are left to the engine. When the engine has to calculate some formulas, the program it runs declares them (and the ones given `#REF!`) as its outputs, so the compiler keeps only what they read (up to 20 000 cells; beyond that the whole program runs and only those cells are written). `--dry-run` says how many the engine calculates and how many are given `#REF!`.
- The writers keep the result a formula cached when a deletion only moved what it reads (the reference is the same shape and is not an error), in XLSX and ODS; they drop it when the formula reads a deleted cell or a range that shrinks. Before, every formula whose text changed lost it.

### Also in this change

- `sheetrs-wasm`: the `json` option of a call is validated and no longer kept in `Call` (it was never read).
