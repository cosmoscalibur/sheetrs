### Changed

- `sheetc` is a replacement of LibreOffice for what it supports, and what it does not support stops the build with an error that names it (`docs/FIDELITY.md#what-stops-a-build`): a function of LibreOffice's catalogue that is not implemented (the inventory is generated from LibreOffice into `functions/namespaces.rs`; a name LibreOffice does not know either stays `#NAME?`), syntax the parser does not read (external workbook references, structured references, `#` spills), a literal `TEXT` code with the language tag of a language the engine has no names for (`[$-407]`), and the document option `precision as shown`. Text of a script the collation does not order as ICU does (Han, kana, Arabic…) is a warning. `sheetc inspect` reports them without stopping.
- The locales are a table generated from LibreOffice itself (`scripts/gen_locale_table.py`) and limited to five the engine reproduces row by row against LibreOffice 26.8: `en-US`, `en-GB`, `es-ES`, `es-CO` and `es-MX` (`en` and `es` are the first of each). `[locale]` is the user's own regional setting and may change any field or define another locale. Dates written as text follow the locale's patterns, as LibreOffice's scanner reads them (`3.1.2024` is not a date in English or Spanish; a date without a year is of the current year; month names by the form written); AM and PM are the locale's text; `.` and `,` that are not a locale's separators are not part of a number. `TEXT` writes `/` in a date code as the locale's date separator, `mmm`/`ddd` with the locale's abbreviations, `AM/PM` with the locale's text, names the language of a `[$-C0A]`-style tag, and gives `#VALUE!` for a tag that is not a hexadecimal id (`[$-en-US]dddd`), as LibreOffice does.
- Dates reach the year 32767 as in LibreOffice (`DATE(32767,12,31)`, `3/1/12345`). `CHAR` and `CODE` follow LibreOffice 26.8 on Linux (`CHAR(128)` is U+FFFD, `CODE("€")` is 226). Booleans are the numbers 1 and 0 in `MATCH`, `LOOKUP` and `COUNTIF`, as in LibreOffice.
- A formula that handles a date serial outside 0001-01-01 … 32768-01-01 while the build folds it stops the build and names the cell; LibreOffice's functions disagree with each other there, so they are not imitated.
- `MATCH` of type 1 or -1, `LOOKUP`, `VLOOKUP` and `HLOOKUP` over an array that is not a range (inline or computed) search as LibreOffice's code for matrices does, so unsorted data give the same positions (compared on 18,000 arrays). `MATCH` with a type other than -1, 0 or 1, or over a two-dimensional range, is an error, and `LOOKUP` over a square range searches its first column, as in LibreOffice.
- Text is ordered by ICU4X's collator and case is mapped by its case mapper, the libraries of LibreOffice's own reference: every script and emoji order as in LibreOffice (72,771 pairs compared in seven languages, no difference) and the warning for scripts the collation did not cover is gone. The `tailoring` setting is removed: the collation follows the language of the locale tag. The equality of text no longer uses the collator: ignoring case it compares the uppercase of both (`ß` is `ẞ`), and `UPPER`, `LOWER` and `PROPER` use ICU's full case mappings with LibreOffice's exceptions, as LibreOffice does (13,304 equality checks and 1,329 mappings compared). Costs: about 1.3 MB more in the binaries, 108 ns per comparison and about 12 s more in a cold build.
- Stops the build: a `TEXT` code whose language the engine has no names for, a date serial outside LibreOffice's range while the build evaluates, and `XLOOKUP` search modes 2 and -2 over a range.
- `COUNTIF` and the other criteria functions with `>`, `<`, `>=` or `<=` alone as the criterion compare the text of the cells with the empty text, as LibreOffice does.
- Regular expressions are read as ICU reads them, as far as it was compared with LibreOffice: a subset of its syntax (literals, `.`, `\d \w \s` and their negations, sets, groups, alternation, quantifiers with their lazy forms, for patterns that cannot match the empty text) is written for the `regex` engine with ICU's meanings (`.` leaves out `\v` and `\f`, `\s` is the Unicode white space), a criterion needs its first match to be the whole text (`a|ab` does not match `ab`), and a text with only `{` and `}` among its special characters is searched as written. Anything else stops the build (anchors, `\b`, look-around, back-references, options, `\p{…}`, patterns that can match the empty text, invalid patterns, patterns computed from data that changes). About 40,000 pattern and text pairs were compared with LibreOffice 26.8. The old empty-match rule is gone with the patterns it served.
- What the build cannot tell because it depends on an input (a `TEXT` code, a search pattern, an `XLOOKUP` search mode) no longer stops it: it warns, and a run that meets a case the engine does not reproduce (a `TEXT` language outside the table, a regular expression outside the subset, `XLOOKUP` modes 2 and -2 over a range, a date serial outside LibreOffice's range) gives the new error value `#NOT_IMPLEMENTED!` in the cell. When the build knows the data, it still stops. See `docs/FIDELITY.md#parity-limits-what-is-known-and-what-only-a-run-shows`.
