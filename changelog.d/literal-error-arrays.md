### Fixed

- An error written in the formula in the arguments of the functions that read arrays or lists of them is read as `LibreOffice` reads it: `SUMPRODUCT`, `SUMX2MY2`, `SUMX2PY2`, `SUMXMY2`, `COVAR`, `COVARIANCE.P`/`.S`, `HSTACK`, `VSTACK`, `TEXTSPLIT`, `FOURIER`, `CHOOSECOLS`, `CHOOSEROWS` and the `…IFS` (`SUMPRODUCT("a",#NAME?)` is 0, `SUMPRODUCT(#NAME?,Data!A1:A3)` is `#VALUE!`, `VSTACK(1,#NAME?)` is 1, `TEXTSPLIT("a",#NAME?)` is `a`). An error element of an array next to a text no longer makes `SUMPRODUCT`, `SUMX2MY2` and `SUMX2PY2` an error, a text is `#VALUE!` for `SUMXMY2` and `COVAR`, and an empty cell is 0 for `SUMXMY2`. `FORECAST.ETS…` with an error written in a series next to a series of several cells is `Err:502`.
- A bare `#REF!` is read per file as `LibreOffice` reads it when it opens that file: the ODS reader no longer forces `#REF!` on a cell with a bare `#ref!` whatever the file caches: it reads the error of an XLSX import (`#NAME?`) as `#REF!`, since `LibreOffice` calculates such a cell when it opens the file, and takes the error `LibreOffice` itself cached (`Err:504`, `Err:539`) as it is (a bare `#REF!` in an ODS array is `Err:539`, as any error written in an array); the semantics ODS fixtures are the ODS recalculated by `LibreOffice`. In an ODS the last argument of `IFNA` written empty is 0.
