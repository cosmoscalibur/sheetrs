### Changed

- A conversion of formulas to values converts what the formulas calculate, not what the file caches (`sheetrs edit --formula-to-value`, `Book.formula_to_value` in Rust, Python and WebAssembly). The cells it names are what the engine is asked for (it calculates them and what they read, nothing else of the workbook: `sheetrs_compiler::Only`), and the pass that writes the file writes each as a value in place of the formula, with the deletions, in the same pass: there is no calculation of every formula followed by a pass of its own. LibreOffice converts the cached results of an XLSX, and of an ODS the ones it did not calculate when it loaded the file (`rate*2` cached as 140 was converted as 14 or as 140 depending on the format). With `--use-cache` (`use_cache`, `useCache`) the conversion still reads the results the file holds: the cached ones where the plan reaches nothing, the engine's where it does. On a workbook of 2.4 M formulas the XLSX that caches nothing is converted faster (no calculation of the whole workbook, `docs/performance.md`), and an ODS, which was streamed from its cached results in 17 MB, now needs the engine (more time and memory, as any run that calculates).
- A workbook the engine cannot calculate has its cached results converted when nothing before the conversion leaves them stale and the file does not say they are stale, and the report says so with a warning of code `CONVERTED_FROM_CACHE`; if they may be stale the run stops, as before.

### Added

- `sheetrs_compiler::Only` and `Options::only`/`Spec::only` (the outputs of a recalculation are the formulas inside some cells), `sheetrs_answer::fill_template_to_also` (the results of a program written with the modifications of the same pass, a formula the pass converts becoming its result), and a `CellEdit::Cached` in a cell that `formula_to_value` covers writes the result as a value, in an XLSX and in an ODS.
