### Added

- WebAssembly target of the compiler: `sheetc build FILE --target wasm -o book.wasm` writes a module of the workbook (the program added to a runtime base module, `sheetrs-rt-wasm`) that needs no imports and no glue; a browser or Node (the hosts it is tested in) instantiates it and calls `sheetrs_calculate`, `sheetrs_write` (the workbook with the answer, with `--embed-template` or `--recalculate`) and `sheetrs_meta`. `scripts/build-wasm-rt.sh` builds the two base modules (the engine; the engine with the readers and writers) and puts them next to `sheetc`, which never falls back to another file; the release archives carry them.
- `compile_workbook(bytes, ext, options)` in the `sheetrs-wasm` package compiles a workbook into such a module in the browser (the only target there is WebAssembly). The package carries the base modules inside: one package, with nothing to fetch.
- The web demo (`docs/`) offers every tool of the package: lint (report, table, SARIF), statistics, query, edit (a plan of operations), calculate (a form with the inputs of the model), evaluate, and compile to a WebAssembly module that runs in the page. `sheetrs-wasm/tests/demo.mjs` drives it in Chromium with screenshots; `scripts/package-wasm.sh --demo` puts the package in `docs/pkg`.
