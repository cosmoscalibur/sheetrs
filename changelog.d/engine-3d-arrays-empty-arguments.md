### Changed

- `sheetrs-compiler`, `sheetrs-formula`: a text with an array that the parser refuses is no longer a build error but what LibreOffice makes of it: the error of the cell (`{1,2}{3}` is `Err:509`, `{1,2}}` `Err:508`, `{1 2}` and `{"x",'y'}` `Err:539`, `{` and `{1,2}{` `Err:512`, `{{1}}` `Err:533`) or the text with what was left open closed (`{1,2` is `{1,2}`, `SUM({1,2},{3` is `SUM({1,2},{3})`); `SUM(1,` is `Err:511`, `1+` `Err:520`, `1)` `Err:508`. The range operator over an array is `Err:502`.
- `sheetrs-compiler`, `sheetrs-engine`, `sheetrs-formula`: a reference over several sheets (`Data:Wide!A1:A3` as an XLSX writes it, `Data!A1:Wide!A3`) is the same area on every sheet from the first to the last, in the order of the workbook, as in LibreOffice. The functions that go through the cells (`SUM`, `COUNT`, `AVERAGE`, `MAX`, `LARGE`, `MEDIAN`…) take all of it; `ROWS`, `COLUMNS`, `SHEETS` and `ROW` add the extent up; `SUMIF`, `COUNTIF`, `MATCH`, `VLOOKUP`, `SUMPRODUCT` refuse it with `Err:504`, `INDEX` with `#REF!`; anywhere else it is `#VALUE!`. Before, `Data!A1:Wide!A1` was read as `Data!A1:A1` without a word, and `Data:Wide!A1` was `#REF!`. What each function does (`functions/threed_table.rs`) is probed for the whole registry (`scripts/probe_3d.py`). The parser reads `T:V!A1` as one reference over the sheets (`'My Sheet:Other'!A1` when the names need quotes).
- `sheetrs-compiler`: a sheet that is not in the workbook is `#NAME?` in the formula of an XLSX (it was `#REF!`), as in LibreOffice.
- `sheetrs-engine`: an array written in the formula (or the result of a function that gives one) is taken one element at a time by a function that takes one value there, in a formula that is not an array formula too: `SUM(ABS({-1;-2}))` is 3, `SUM(IF({1;0;1},{5;9;9},{7;7;7}))` 21, `SUM(CHOOSE({1;2},10,20))` 30, `INDEX(IF({1;0},{5;9},"a"),2)` `a`, `SUM(DATE(2020,{1;2},1))`; a function that takes arrays (`SUM`, `MAX`, `SUMPRODUCT`, `MATCH`'s array…) takes it whole. The arguments that lift (`functions/lift_table.rs`) are probed for the whole registry (`scripts/probe_lift.py`); an array among the arguments turns a range into an array too, arrays of different sizes give `#N/A` where the smaller has no element (a panic before), and a plain value where a range goes is no longer refused in the call over an array. `IF`, `CHOOSE`, `IFERROR` and `IFNA` take arrays of conditions, indexes and values.
- `sheetrs-engine`: the elements of an array are numbers: a boolean that a comparison or an array written in the formula left in it counts in `SUM({1,2}>1)` (1) and is 1 or 0 once picked out (`INDEX({TRUE,FALSE}=1,1,1)` is 1); `ISLOGICAL` of an array is false (true for an array written with `TRUE` first), and `TYPE` of one is 64. `CHOOSE` with an index outside the values is `Err:502`, and `MID` with a start under 1 or a negative length too.
- `sheetrs-compiler`, `sheetrs-engine`: an argument written empty is what LibreOffice makes of it for each function (`functions/omitted_table.rs`, `scripts/probe_omitted.py`): the number 0 (`LOG(10,)`, `DATE(2020,,5)`, `MID("abcdef",,2)`), an empty text (`LEFT("abc",)`, `SUBSTITUTE("abc","b",)`), the argument not written when it is the last (`TAKE(r,)` and `DROP(r,)` are `Err:502`, `SEQUENCE(,3)` has one row), or an error (`IFERROR(,5)` is `Err:518`, `IFNA(NA(),)` is `#N/A`); a range argument written empty is a plain value (`SUMIF(r,">3",)` is `Err:504`).
- `sheetrs-compiler`: new rows of the oracle for these (`scripts/sheets_and_arrays_formulas.txt`), the three probes.
