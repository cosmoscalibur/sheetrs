# Sheetlint Profiling & Architecture

This document captures performance profiling data and architectural insights for optimizing `sheetrs lint`.

---

## Profiling Results

> **Input**: `formulas.xlsx`, generated by `scripts/bench.py fixtures` (see
> [docs/performance.md](../../docs/performance.md#fixtures)): 5 sheets, 3,604,035 used cells, 2,400,005 formulas, 28 MB  
> **Build**: `profiling` Cargo profile with frame pointers, `scripts/benchmark.toml` as the configuration  
> **Run**: 15,053 samples at 499 Hz over one run (about 30 s)

Shares are inclusive `perf` samples (a function plus its callees) over one run. A virtual machine has no hardware
counters, so the profile samples the CPU clock:

```bash
CARGO_TARGET_DIR=target/fp RUSTFLAGS="-C force-frame-pointers=yes" cargo build --profile profiling -p sheetrs-cli
perf record -F 499 -e cpu-clock --call-graph fp ./target/fp/profiling/sheetrs lint -c scripts/benchmark.toml -i <file> > /dev/null
perf report --children --sort symbol -g none
```

The times and the memory of the whole tool are in [docs/performance.md](../../docs/performance.md#sheetrs-lint);
a change that targets the cost of a rule or a phase updates this profile.

tree.

## Current Architecture

### Single-Pass Walker

Every rule implements `WalkerRule` (see [coding patterns](../../docs/coding-patterns.md#the-walker-pattern)).
`WorkbookWalker` traverses the parsed workbook once and calls each rule's hooks:

```mermaid
flowchart LR
    subgraph Parse["Parsing"]
        A[ZIP Archive] --> B[XML Parsing<br/>quick-xml]
        B --> C[Build Workbook<br/>sheets, cells, names]
    end

    subgraph Walk["Rule execution: WorkbookWalker"]
        D[on_workbook_start<br/>all rules] --> E
        subgraph Sheets["for each sheet"]
            E[on_sheet_start] --> F[on_cell<br/>each cell × all rules]
            F --> G[on_sheet_end]
        end
        G --> H[on_workbook_end<br/>all rules]
    end

    C --> D
    H --> I[Sort violations] --> J[Format output]
```
