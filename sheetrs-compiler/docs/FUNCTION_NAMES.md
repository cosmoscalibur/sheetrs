# Function names by file format (LibreOffice 26.8)

Generated by `scripts/function_namespaces.py`: every function of LibreOffice's catalogue is written to an ODS and to an XLSX
and the name each file gives it is paired. A function belongs to a **namespace**, which OpenDocument writes as a prefix; the
same text can name two functions in two namespaces, and the engine registers them as `namespace::NAME`.

| Namespace | Prefix in an ODS | In an XLSX | Functions | What it holds |
| --- | --- | --- | --: | --- |
| `core` | none | the bare name | 385 | The OpenDocument standard (OpenFormula): `SUM`, `IF`, `VLOOKUP`, `CEILING`… |
| `microsoft` | `COM.MICROSOFT.` | `_xlfn.` (bare for `CEILING`, `FLOOR`, `ISO.CEILING`, `NETWORKDAYS.INTL`, `WORKDAY.INTL`) | 101 | What Microsoft defined after ODF 1.2 (`IFS`, `XLOOKUP`, `STDEV.S`…) and Excel's version of a function whose bare name is something else (`CEILING`, `FLOOR`) |
| `libreoffice` | `ORG.LIBREOFFICE.` | `_xlfn.ORG.LIBREOFFICE.` | 11 | LibreOffice's own extensions (`REGEX`, `COLOR`, `ROUNDSIG`, `FOURIER`…) |
| `openoffice` | `ORG.OPENOFFICE.` | `_xlfn.ORG.OPENOFFICE.` or bare (`WEEKS`, `MONTHS`, `ROT13`…) | 12 | Extensions that come from OpenOffice (`ERRORTYPE`, `CONVERT`, `DAYSINMONTH`…) |
| `legacy` | `LEGACY.` | the bare name | 8 | The pre-ODF-1.2 function whose bare name now means another (`FDIST`, `TDIST`, `NORMSDIST`…) |
| add-ins | `COM.SUN.STAR.SHEET.ADDIN.…` | the bare name | 4 | Functions the analysis add-in implements; for the engine they are `core` |

* 353 functions have the same name in both formats (`SUM`, `IF`, `VLOOKUP`…).
* 96 functions of the 2010+ generation are `_xlfn.NAME` in XLSX and `COM.MICROSOFT.NAME` (or `ORG.OPENOFFICE.`/`ORG.LIBREOFFICE.`) in ODS.
* 4 are add-in functions in ODS, plain in XLSX; 8 are `LEGACY.NAME` in ODS and `NAME` in XLSX.
* `EASTERSUNDAY` is bare in an ODS and `_xlfn.ORG.OPENOFFICE.EASTERSUNDAY` in an XLSX: the two formats disagree on its namespace.

## Same text, different function

| Text | In an XLSX it is | In an ODS it is |
| --- | --- | --- |
| `FDIST` | `legacy::FDIST` | `core::FDIST` |
| `FINV` | `legacy::FINV` | `core::FINV` |
| `CEILING` | `microsoft::CEILING` | `core::CEILING` |
| `FLOOR` | `microsoft::FLOOR` | `core::FLOOR` |

A bare `CEILING`/`FLOOR` in an ODS is the OpenDocument function, `core::CEILING` (the signs of number and multiple must agree; its XLSX
export is `CEILING.MATH`/`FLOOR.MATH`, which it is not); Excel's `CEILING`/`FLOOR` are `microsoft::CEILING`/`FLOOR` (`COM.MICROSOFT.CEILING` in an ODS, bare in an XLSX).
`FDIST`/`FINV` in an ODS are the ODF functions (`F.DIST`/`F.INV`'s generation); the legacy ones are `LEGACY.FDIST`/`LEGACY.FINV`.
