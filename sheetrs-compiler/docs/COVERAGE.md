# Function and operator coverage

Generated by `scripts/function_coverage.py` against LibreOffice 26.8.1.1 bf6ef2662401c7d6dce671ab4deb26ee0af3a7c1.

The reference catalogue is the one LibreOffice reports through its own API (`FunctionDescriptions`): every function `soffice` can evaluate, which includes the ones of OpenDocument (OpenFormula) and the Excel-compatible ones. *Implemented* means in the engine's registry; *checked* means that an oracle formula (a formula of `tests/assets/semantics.*` or the probes, whose values LibreOffice computed) uses it.

**516 of 520 LibreOffice functions are implemented (not counting the 11 that no file can use); 505 of them appear in an oracle formula.** The oracle has 28476 formulas in `semantics.*` plus the probes; most functions have one or two formulas, not an exhaustive set of edge cases.

## Not implemented, by category

A workbook that calls any of them does not build: the error names the function and the first cell. This list is the inventory the build checks against (`CATALOGUE` in `functions/namespaces.rs`).

* **Lookup and spreadsheet** (2): `DDE`, `GETPIVOTDATA`
* **Text** (2): `FILTERXML`, `WEBSERVICE`

## Listed by LibreOffice but unusable in a file

A formula that names them is `#NAME?` in an OpenDocument file, in an XLSX file (bare, with `_xlfn.` or with `_xlfn.ORG.LIBREOFFICE.`) and in LibreOffice's own grammar, so no workbook can call them and they are not counted above: `CONVERT_OOO`, `CUMIPMT_ADD`, `CUMPRINC_ADD`, `EFFECT_ADD`, `GCD_EXCEL2003`, `ISEVEN_ADD`, `ISODD_ADD`, `LCM_EXCEL2003`, `NETWORKDAYS_EXCEL2003`, `NOMINAL_ADD`, `WEEKNUM_EXCEL2003`.

## Resolved while compiling

`LET` (by substitution), and `ISFORMULA` and `FORMULA` of a literal reference (from what the cell holds) are resolved by the compiler, not by the engine's registry; `ISFORMULA` and `FORMULA` of a reference computed at run time stop the build.

## Implemented but not checked against soffice

`CEILING.XCL`, `EASTERSUNDAY`, `FILTER`, `FLOOR.XCL`, `FORMULA`, `HYPGEOMDIST`, `NOW`, `RAND`, `SKEWP`, `SORT`, `TODAY`

Functions are registered by their LibreOffice name; the names a file gives them are in `docs/FUNCTION_NAMES.md` (`ISNUMBER` counts booleans as numbers, and `EASTERSUNDAY`).

## Operators and syntax

Implemented: `+ - * / ^ &`, the comparisons `= <> < <= > >=`, unary `-` and `+`, postfix `%`, the range operator `:` (also between computed references, as in `A1:INDEX(...)`), whole-column and whole-row ranges, sheet-qualified references, defined names, array constants and `{...}` array formulas. In the oracle: every arithmetic operator, `&`, `%` and `:`, `=`, `<>`, `<`, `>` and `>=` (some with a single formula; `<=` appears only in probes).

Not implemented (a build stops, naming the formula): reference **intersection** (space) and **union** (`,` inside parentheses in Excel, `~` in OpenDocument), the **spill** operator `A1#`, **structured references** to tables (`Table1[Col]`), and **external workbook** references (`[Book.xlsx]Sheet!A1`).

## Excel functions this LibreOffice does not have

Checked against the catalogue above (the list of Excel functions is from the Excel documentation, not generated): `LAMBDA`, `MAP`, `REDUCE`, `SCAN`, `BYROW`, `BYCOL`, `MAKEARRAY`, `ARRAYTOTEXT`, `VALUETOTEXT`, `GROUPBY`, `PIVOTBY`.

## Behavior parity

Behavior is checked only where `soffice` can answer. The reference is LibreOffice for every file (also XLSX); the oracle is its own results. Where it differs from Excel, the engine gives LibreOffice's answer, documented in [FIDELITY.md](FIDELITY.md) next to Excel's documented behavior, which is not checked against Excel itself: no Excel is available here.
